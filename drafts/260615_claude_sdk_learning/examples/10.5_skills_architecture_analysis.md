# Skills 架构深度分析

## 1. Skills 是什么？

**Skills = 领域知识 + 工作流指导 + MCP 工具映射**

Skills 不是可执行代码，而是：
- 📖 **知识层**：告诉模型如何完成特定领域任务
- 🗺️ **工作流**：定义步骤、决策点、硬约束
- 🔗 **工具映射**：指向可用的 MCP 工具

```
用户需求 → Skill tool → 注入 SKILL.md → 模型根据 Skill 调用 MCP 工具 → 完成任务
```

## 2. Skills 目录结构与发现机制

### 2.1 官方 Skills（superpowers plugin）

```
/root/.claude/plugins/cache/claude-plugins-official/superpowers/5.1.0/
├── .claude-plugin/
│   └── plugin.json          # Plugin 元信息
└── skills/
    ├── brainstorming/SKILL.md
    ├── test-driven-development/SKILL.md
    ├── systematic-debugging/SKILL.md
    └── ...
```

**发现机制**：
- Plugin 通过 `/root/.claude/plugins/` 自动发现
- Plugin 的 `skills/` 目录下的所有 `SKILL.md` 自动注册
- 通过 `plugin.json` 声明插件元信息

---

### 2.2 项目级 Skills（ANIFORCE）

```
backend/runtime/skills/
├── campaign-management/
│   └── SKILL.md
├── project-management/
│   └── SKILL.md
├── data-analysis/
│   └── SKILL.md
└── hitl-operations/
    └── SKILL.md
```

**问题**：
- SDK 默认从 `.claude/skills/` 查找项目 Skills
- ANIFORCE 的 Skills 在 `backend/runtime/skills/`
- 导致测试中 Skill tool 报 "skill not available"

**解决方案**：
1. 移动到 `.claude/skills/`（推荐）
2. 创建符号链接：`ln -s backend/runtime/skills .claude/skills`
3. 或通过 Plugin 机制包装（见下文）

---

### 2.3 动态注入 Skills（AiToEarn）

AiToEarn 有独特的动态 Skills 注入机制：

```typescript
// apps/aitoearn-ai/src/core/agent/skill-init.service.ts

@Injectable()
export class SkillInitService implements OnModuleInit {
  private readonly sourceDir = path.join(__dirname, 'skills')
  private readonly targetDir = path.join(process.cwd(), '.claude-session', '.claude', 'skills')

  async onModuleInit(): Promise<void> {
    this.initializeSkills()  // 应用启动时复制 Skills
  }

  private initializeSkills(): void {
    fs.mkdirSync(this.targetDir, { recursive: true })
    
    for (const skillName of SKILL_DIRECTORIES) {
      this.copySkillDirectory(skillName)  // 从 src/core/agent/skills/ 复制到运行时
    }
  }
}
```

**架构**：
```
源码目录: apps/aitoearn-ai/src/core/agent/skills/
                                          ├── generating-videos/SKILL.md
                                          ├── editing-videos/SKILL.md
                                          └── ...
                ↓ 应用启动时复制
运行时目录: .claude-session/.claude/skills/
                                    ├── generating-videos/SKILL.md
                                    ├── editing-videos/SKILL.md
                                    └── ...
```

**优势**：
- ✅ Skills 源码与应用代码在一起（便于版本管理）
- ✅ 运行时动态注入（无需手动复制）
- ✅ 支持租户隔离（每个会话独立 `.claude-session/`）

**劣势**：
- ❌ 需要应用启动时初始化
- ❌ Skills 更新需要重启应用

## 3. Skills 工作流程

### 3.1 SDK 配置 Skills

```python
from claude_agent_sdk import ClaudeAgentOptions

options = ClaudeAgentOptions(
    skills=["campaign-management"],  # 启用特定 Skill
    # skills="all",                  # 启用所有 Skill
    # skills=[],                     # 禁用所有 Skill
    allowed_tools=["Skill"],          # 必须允许 Skill 工具
    setting_sources=["project"],      # 必须包含 project 才能加载 SKILL.md
    cwd=str(project_root),           # 设置工作目录
)
```

**配置项说明**：
- `skills`：Skills 白名单（None = 使用 CLI 默认，[] = 禁用）
- `allowed_tools`：必须包含 "Skill" 工具
- `setting_sources`：必须包含 "project" 才能加载项目 SKILL.md
- `cwd`：工作目录（影响 Skills 发现路径）

---

### 3.2 Skill 调用流程

```
1. 用户: "Use campaign-management skill to list campaigns"
            ↓
2. 模型: 判断需要调用 Skill
            ↓
3. Tool Call: Skill(skill="campaign-management", args="list campaigns")
            ↓
4. SDK: 读取 .claude/skills/campaign-management/SKILL.md
            ↓
5. SDK: 注入 SKILL.md 内容到 context
            ↓
6. 模型: 根据 Skill 内容，调用 MCP 工具
            ↓
7. Tool Call: mcp__campaign__list_campaigns(project_id="proj_001")
            ↓
8. MCP Server: 执行工具，返回结果
            ↓
9. 模型: 根据 Skill 工作流，格式化响应给用户
```

---

### 3.3 SKILL.md 结构

```markdown
---
name: campaign-management
description: 广告计划管理：创建、查询、更新、删除、暂停/启动广告计划
---

# 广告计划管理 Skill

## 目标
帮助用户管理广告计划的全生命周期

## 输入
- 用户自然语言需求
- 广告计划 ID

## 输出
- 结构化广告计划信息
- 操作确认消息

## 可用的 MCP Tools

### 1. list_campaigns
查询广告计划列表

**参数**：
- `project_id` (string, 可选): 项目 ID

**返回**：广告计划列表

### 2. create_campaign
创建新广告计划

**参数**：
- `project_id` (string, 必填): 所属项目 ID
- `name` (string, 必填): 广告计划名称
- `budget` (number, 必填): 预算金额

**返回**：创建的广告计划对象

## 工作流

### 工作流 1：创建广告计划

**触发条件**：
- 用户说"创建广告计划"
- 用户说"投放 Facebook 广告"

**步骤**：
1. 确定所属项目
2. 提取广告计划信息
3. 验证参数
4. 调用 MCP Tool
5. 返回结果

## 硬约束

1. 广告计划必须属于某个项目
2. 预算必须 > 0
3. 删除操作必须要求确认
```

**关键部分**：
- **frontmatter**：name（Skill 名称）、description（触发场景）
- **可用 MCP Tools**：列出所有相关工具及其参数
- **工作流**：详细步骤和决策点
- **硬约束**：必须遵守的规则

## 4. Skills vs MCP 的关系

| 维度 | Skills | MCP |
|------|--------|-----|
| **本质** | 知识层（how to use） | 能力层（what you can do） |
| **形式** | Markdown 文档（SKILL.md） | 可执行工具（Python/TypeScript 函数） |
| **作用** | 指导模型调用工具 | 提供实际能力 |
| **触发** | Skill tool（显式调用） | MCP 工具调用 |
| **注入时机** | Skill tool 调用时 | 会话启动时 |
| **内容** | 工作流、决策点、约束 | 工具签名、参数、返回值 |
| **适用场景** | 复杂领域任务 | 基础能力（文件、API、数据库） |

**协作关系**：
```
Skills 定义"做什么"、"怎么做" → MCP 提供"能做什么"
```

**示例**：
- Skill: "广告计划管理 Skill 定义创建广告的 5 个步骤"
- MCP: "`create_campaign` 工具实现创建广告的数据库操作"

### 方案 B：动态注入 Skills（类似 AiToEarn）

```python
# 1. 应用启动时复制 Skills
import shutil
from pathlib import Path

def init_skills(session_id: str):
    source_dir = Path("backend/runtime/skills")
    target_dir = Path(f".claude-sessions/{session_id}/.claude/skills")
    
    target_dir.mkdir(parents=True, exist_ok=True)
    
    for skill_dir in source_dir.iterdir():
        if skill_dir.is_dir() and (skill_dir / "SKILL.md").exists():
            shutil.copytree(skill_dir, target_dir / skill_dir.name, dirs_exist_ok=True)

# 2. 配置 SDK
session_id = "session_001"
init_skills(session_id)

options = ClaudeAgentOptions(
    skills="all",
    allowed_tools=["Skill", "mcp__*"],
    setting_sources=["project"],
    cwd=f".claude-sessions/{session_id}",
)
```

**优势**：
- ✅ Skills 源码与应用在一起
- ✅ 支持多租户隔离

**劣势**：
- ❌ 需要额外初始化逻辑
- ❌ Skills 更新需要手动同步

## 6. Skills 最佳实践

### 6.1 Skills 定义

**DO**：
- ✅ frontmatter 包含 name 和 description
- ✅ description 明确触发场景
- ✅ 列出所有可用 MCP 工具及参数
- ✅ 定义清晰的工作流和决策点
- ✅ 明确硬约束（必须遵守的规则）

**DON'T**：
- ❌ 不要把 Skills 写成泛泛的说明文
- ❌ 不要省略 MCP 工具签名
- ❌ 不要假设模型知道工具参数
- ❌ 不要忽略错误处理流程

---

### 6.2 Skills 与 MCP 集成

**DO**：
- ✅ Skills 引用真实的 MCP 工具名称
- ✅ Skills 参数与 MCP 工具签名一致
- ✅ Skills 描述 MCP 工具的组合使用
- ✅ Skills 定义 MCP 工具调用顺序

**DON'T**：
- ❌ 不要在 Skills 中硬编码业务逻辑
- ❌ 不要让 Skills 直接访问数据库
- ❌ 不要在 Skills 中实现工具能力

---

### 6.3 Skills 粒度

**合适粒度**：
- ✅ 一个 Skill = 一个领域任务
- ✅ 示例：广告计划管理、项目管理、数据分析

**过细**：
- ❌ 一个 Skill = 一个 MCP 工具（没必要）
- ❌ 示例：创建广告 Skill、查询广告 Skill（应合并）

**过粗**：
- ❌ 一个 Skill = 整个应用（无法复用）
- ❌ 示例：ANIFORCE 全功能 Skill（应拆分）

---

## 7. 总结：Skills 三层架构

```
┌─────────────────────────────────────────┐
│  用户需求（自然语言）                      │
└─────────────────┬───────────────────────┘
                  │
                  ▼
┌─────────────────────────────────────────┐
│  Skills 层（知识层）                       │
│  - SKILL.md 定义工作流                     │
│  - 指导模型如何完成任务                     │
│  - 映射到 MCP 工具                        │
└─────────────────┬───────────────────────┘
                  │
                  ▼
┌─────────────────────────────────────────┐
│  MCP 层（能力层）                          │
│  - @tool 定义工具签名                      │
│  - 实现具体能力                           │
│  - 返回结构化数据                         │
└─────────────────┬───────────────────────┘
                  │
                  ▼
┌─────────────────────────────────────────┐
│  业务层（数据层）                          │
│  - Service/Repository                    │
│  - 数据库/API 调用                        │
│  - 业务逻辑                              │
└─────────────────────────────────────────┘
```

**职责划分**：
- **Skills**：声明式知识（告诉模型怎么做）
- **MCP**：命令式能力（提供工具）
- **业务层**：实际执行（操作数据）

## 8. 问题排查

### 问题 1：Skill tool 报 "skill not available"

**原因**：
- Skills 目录不在 `.claude/skills/`
- `setting_sources` 未包含 "project"
- `cwd` 配置错误

**解决**：
```python
options = ClaudeAgentOptions(
    skills=["campaign-management"],
    allowed_tools=["Skill"],
    setting_sources=["project"],  # 必须包含
    cwd=str(project_root),       # 必须指向项目根
)
```

---

### 问题 2：Skill 调用成功但模型不遵循工作流

**原因**：
- SKILL.md 描述不够清晰
- 缺少硬约束
- MCP 工具签名不匹配

**解决**：
- 明确工作流步骤
- 添加硬约束（MUST / CRITICAL）
- 验证 MCP 工具名称和参数

---

### 问题 3：Skills 更新不生效

**原因**：
- 动态注入的 Skills 未重新复制
- CLI 缓存未清除

**解决**：
```bash
# 方案 A：重启应用（动态注入）
# 方案 B：清除缓存
rm -rf .claude-sessions/*/
```
