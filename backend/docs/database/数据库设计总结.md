# ANIMAGUS 数据库设计总结

## 概述

ANIMAGUS 后端采用混合数据库架构：
- **PostgreSQL**：存储结构化数据（用户、项目、广告系列、素材、监控指标）
- **MongoDB**：存储非结构化数据（AI 对话历史、会话信息）

本文档主要描述 PostgreSQL 数据库的表结构设计。

---

## 数据库技术栈

| 组件 | 版本 | 用途 |
|------|------|------|
| PostgreSQL | 15+ | 关系型数据存储 |
| MongoDB | 6+ | 对话历史存储 |
| SQLAlchemy | 2.0+ | ORM 框架 |
| Alembic | 1.13+ | 数据库迁移工具 |

## 表结构设计

### 1. users（用户表）

**用途**：存储系统用户的基本信息和认证数据

| 字段名 | 类型 | 约束 | 说明 |
|--------|------|------|------|
| `id` | String(36) | PRIMARY KEY | UUID 主键 |
| `email` | String(255) | UNIQUE, NOT NULL, INDEX | 邮箱地址（登录账号） |
| `password_hash` | String(255) | NOT NULL | 密码哈希值（bcrypt） |
| `name` | String(100) | NULLABLE | 用户名称 |
| `created_at` | DateTime | NOT NULL | 创建时间（UTC） |
| `updated_at` | DateTime | NOT NULL | 更新时间（UTC） |

**关系**：
- `projects` - 一对多关系，用户可以创建多个项目
- `materials` - 一对多关系，用户可以上传多个素材

**索引**：
- PRIMARY KEY: `id`
- UNIQUE INDEX: `email`

**级联删除**：删除用户时自动删除其所有项目和素材

---

### 2. projects（项目表）

**用途**：存储游戏营销项目的基本信息、预算和状态

| 字段名 | 类型 | 约束 | 说明 |
|--------|------|------|------|
| `id` | String(36) | PRIMARY KEY | UUID 主键 |
| `user_id` | String(36) | FOREIGN KEY, NOT NULL, INDEX | 关联用户 ID |
| `name` | String(255) | NOT NULL | 项目名称 |
| `description` | Text | NULLABLE | 项目描述 |
| `game_type` | String(50) | NULLABLE | 游戏类型（如 RPG、SLG） |
| `target_market` | String(100) | NULLABLE | 目标市场（如东南亚、北美） |
| `tags` | Text | NULLABLE | 标签（JSON 数组格式） |
| `total_budget` | Float | NOT NULL | 总预算金额 |
| `spent` | Float | DEFAULT 0.0 | 已花费金额 |
| `status` | Enum | NOT NULL, INDEX | 项目状态 |
| `manager` | String(100) | NULLABLE | 项目负责人 |
| `start_date` | Date | NULLABLE | 项目开始日期 |
| `end_date` | Date | NULLABLE | 项目结束日期 |
| `created_at` | DateTime | NOT NULL | 创建时间（UTC） |
| `updated_at` | DateTime | NOT NULL | 更新时间（UTC） |

**枚举值**：
- `status`: `active`（进行中）、`paused`（已暂停）、`completed`（已完成）

**关系**：
- `user` - 多对一关系，项目属于某个用户
- `campaigns` - 一对多关系，项目包含多个广告系列

**索引**：
- PRIMARY KEY: `id`
- INDEX: `user_id`
- INDEX: `status`

**级联删除**：删除项目时自动删除其所有广告系列

---

### 3. campaigns（广告系列表）

**用途**：存储广告投放计划的配置、预算和状态

| 字段名 | 类型 | 约束 | 说明 |
|--------|------|------|------|
| `id` | String(36) | PRIMARY KEY | UUID 主键 |
| `project_id` | String(36) | FOREIGN KEY, NOT NULL, INDEX | 关联项目 ID |
| `name` | String(255) | NOT NULL | 广告系列名称 |
| `description` | Text | NULLABLE | 广告系列描述 |
| `platform` | Enum | NOT NULL, INDEX | 投放平台 |
| `budget` | Float | NOT NULL | 预算金额 |
| `spent` | Float | DEFAULT 0.0 | 已花费金额 |
| `status` | Enum | NOT NULL, INDEX | 广告系列状态 |
| `material_ids` | Text | NULLABLE | 关联素材 ID 列表（JSON 数组） |
| `start_date` | Date | NULLABLE | 投放开始日期 |
| `end_date` | Date | NULLABLE | 投放结束日期 |
| `config` | Text | NULLABLE | 平台特定配置（JSON 格式） |
| `created_at` | DateTime | NOT NULL | 创建时间（UTC） |
| `updated_at` | DateTime | NOT NULL | 更新时间（UTC） |

**枚举值**：
- `platform`: `TikTok`、`Google`、`Meta`
- `status`: `draft`（草稿）、`running`（投放中）、`review`（审核中）、`paused`（已暂停）、`completed`（已完成）

**关系**：
- `project` - 多对一关系，广告系列属于某个项目
- `metrics` - 一对多关系，广告系列包含多条监控指标记录

**索引**：
- PRIMARY KEY: `id`
- INDEX: `project_id`
- INDEX: `platform`
- INDEX: `status`

**辅助方法**：
- `get_material_ids()` - 解析 JSON 获取素材 ID 列表
- `set_material_ids(ids)` - 将素材 ID 列表序列化为 JSON
- `add_material(material_id)` - 添加素材关联
- `remove_material(material_id)` - 移除素材关联

**级联删除**：删除广告系列时自动删除其所有监控指标

---

### 4. materials（素材表）

**用途**：存储广告素材的元数据和关联关系

| 字段名 | 类型 | 约束 | 说明 |
|--------|------|------|------|
| `id` | String(36) | PRIMARY KEY | UUID 主键 |
| `user_id` | String(36) | FOREIGN KEY, NOT NULL, INDEX | 关联用户 ID |
| `project_ids` | Text | NULLABLE | 关联项目 ID 列表（JSON 数组） |
| `campaign_ids` | Text | NULLABLE | 关联广告系列 ID 列表（JSON 数组） |
| `name` | String(255) | NULLABLE | 素材名称 |
| `type` | Enum | NOT NULL, INDEX | 素材类型 |
| `status` | Enum | NOT NULL, INDEX | 素材状态 |
| `url` | Text | NOT NULL | 素材文件 URL |
| `thumbnail_url` | Text | NULLABLE | 缩略图 URL |
| `ctr_estimate` | Float | NULLABLE | 预估点击率 |
| `tags` | Text | NULLABLE | 标签（JSON 数组格式） |
| `duration` | Integer | NULLABLE | 视频时长（秒） |
| `file_size` | Integer | NULLABLE | 文件大小（字节） |
| `created_at` | DateTime | NOT NULL | 创建时间（UTC） |

**枚举值**：
- `type`: `a_segment`（A 段素材）、`b_segment`（B 段素材）、`c_segment`（C 段素材）、`full_video`（完整视频）
- `status`: `running`（投放中）、`ready`（待投放）、`fatigue`（已疲劳）

**关系**：
- `user` - 多对一关系，素材属于某个用户
- 通过 `project_ids` 和 `campaign_ids` 实现与项目和广告系列的多对多关联

**索引**：
- PRIMARY KEY: `id`
- INDEX: `user_id`
- INDEX: `type`
- INDEX: `status`

**辅助方法**：
- `get_project_ids()` / `set_project_ids(ids)` - 项目关联管理
- `add_project(project_id)` / `remove_project(project_id)` - 添加/移除项目关联
- `get_campaign_ids()` / `set_campaign_ids(ids)` - 广告系列关联管理
- `add_campaign(campaign_id)` / `remove_campaign(campaign_id)` - 添加/移除广告系列关联

---

### 5. metrics（监控指标表）

**用途**：存储广告投放的实时监控数据和性能指标

| 字段名 | 类型 | 约束 | 说明 |
|--------|------|------|------|
| `id` | String(36) | PRIMARY KEY | UUID 主键 |
| `campaign_id` | String(36) | FOREIGN KEY, NOT NULL, INDEX | 关联广告系列 ID |
| `timestamp` | DateTime | NOT NULL, INDEX | 数据时间戳（UTC） |
| `platform` | String(50) | NOT NULL | 平台名称 |
| **核心指标** | | | |
| `impressions` | Integer | DEFAULT 0 | 曝光量 |
| `clicks` | Integer | DEFAULT 0 | 点击量 |
| `conversions` | Integer | DEFAULT 0 | 转化量 |
| `installs` | Integer | DEFAULT 0 | 安装量 |
| **成本指标** | | | |
| `spend` | Float | DEFAULT 0.0 | 花费金额 |
| `revenue` | Float | DEFAULT 0.0 | 收入金额 |
| **转化指标** | | | |
| `ctr` | Float | DEFAULT 0.0 | 点击率（Click-Through Rate） |
| `cvr` | Float | DEFAULT 0.0 | 转化率（Conversion Rate） |
| `cpa` | Float | DEFAULT 0.0 | 单次获客成本（Cost Per Action） |
| `cpi` | Float | DEFAULT 0.0 | 单次安装成本（Cost Per Install） |
| `roi` | Float | DEFAULT 0.0 | 投资回报率（Return on Investment） |

**关系**：
- `campaign` - 多对一关系，指标记录属于某个广告系列

**索引**：
- PRIMARY KEY: `id`
- INDEX: `campaign_id`
- INDEX: `timestamp`

**查询优化**：
- 按时间范围查询：使用 `timestamp` 索引
- 按广告系列查询：使用 `campaign_id` 索引
- 聚合查询：可按小时/天/周进行分组统计

```
┌─────────────┐
│    users    │
│  (用户表)    │
└──────┬──────┘
       │ 1
       │
       ├─────────────────────────────────┐
       │                                 │
       │ N                               │ N
┌──────▼──────┐                   ┌──────▼──────┐
│  projects   │                   │  materials  │
│  (项目表)    │                   │  (素材表)    │
└──────┬──────┘                   └─────────────┘
       │ 1                               │
       │                                 │ N (通过 JSON)
       │ N                               │
┌──────▼──────┐                          │
│  campaigns  │◄─────────────────────────┘
│ (广告系列表) │
└──────┬──────┘
       │ 1
       │
       │ N
┌──────▼──────┐
│   metrics   │
│ (监控指标表) │
└─────────────┘
```

**关系说明**：
- **users → projects**：一对多（一个用户可以创建多个项目）
- **users → materials**：一对多（一个用户可以上传多个素材）
- **projects → campaigns**：一对多（一个项目可以包含多个广告系列）
- **campaigns → metrics**：一对多（一个广告系列有多条监控数据）
- **materials ↔ projects**：多对多（通过 JSON 数组实现）
- **materials ↔ campaigns**：多对多（通过 JSON 数组实现）

## 设计特点

### 1. UUID 主键
所有表使用 UUID (String(36)) 作为主键，优势：
- 全局唯一，便于分布式系统
- 避免主键冲突
- 不暴露业务信息（如用户数量）

### 2. 级联删除
合理使用级联删除策略：
- 删除用户 → 自动删除其项目和素材
- 删除项目 → 自动删除其广告系列
- 删除广告系列 → 自动删除其监控指标

### 3. 枚举类型
使用 Enum 确保数据一致性：
- `ProjectStatus`: active, paused, completed
- `CampaignStatus`: draft, running, review, paused, completed
- `Platform`: TikTok, Google, Meta
- `MaterialType`: a_segment, b_segment, c_segment, full_video
- `MaterialStatus`: running, ready, fatigue

### 4. JSON 存储
灵活存储数组和对象：
- `tags` - 标签数组
- `material_ids` - 素材 ID 列表
- `project_ids` / `campaign_ids` - 多对多关联
- `config` - 平台特定配置

### 5. 时间戳
标准时间字段：
- `created_at` - 创建时间（自动设置）
- `updated_at` - 更新时间（自动更新）
- `timestamp` - 数据时间戳（metrics 表）

### 6. 索引优化
在常查询字段上建立索引：
- 外键字段：`user_id`, `project_id`, `campaign_id`
- 状态字段：`status`
- 时间字段：`timestamp`
- 唯一字段：`email`

### 7. 辅助方法
提供便捷的 JSON 操作方法：
- Campaign: `get_material_ids()`, `add_material()`, `remove_material()`
- Material: `get_project_ids()`, `add_project()`, `remove_project()`
- Material: `get_campaign_ids()`, `add_campaign()`, `remove_campaign()`

## MongoDB 存储

除了 PostgreSQL，系统还使用 MongoDB 存储非结构化数据：

### conversations（对话集合）
存储 AI 对话历史记录

**字段**：
- `session_id` - 会话 ID
- `user_id` - 用户 ID
- `messages` - 消息数组
  - `role` - 角色（system/user/assistant）
  - `content` - 消息内容
  - `timestamp` - 时间戳
- `created_at` - 创建时间
- `updated_at` - 更新时间

### sessions（会话集合）
存储会话元数据

**字段**：
- `session_id` - 会话 ID
- `user_id` - 用户 ID
- `title` - 会话标题
- `message_count` - 消息数量
- `created_at` - 创建时间
- `updated_at` - 最后更新时间

## 性能优化建议

### 1. 查询优化
- 使用索引字段进行查询和排序
- 避免在 JSON 字段上进行复杂查询
- 使用分页查询大量数据

### 2. 连接池配置
```python
# PostgreSQL 连接池
pool_size=10
max_overflow=20
pool_pre_ping=True
```

### 3. 批量操作
- 使用 `bulk_insert_mappings()` 批量插入
- 使用 `bulk_update_mappings()` 批量更新

### 4. 读写分离
- 主库：写操作
- 从库：读操作（报表、统计）

### 5. 数据归档
- metrics 表定期归档历史数据
- 保留最近 3 个月的热数据
- 历史数据迁移到归档表或数据仓库

## 安全建议

### 1. 密码安全
- 使用 bcrypt 哈希密码
- 设置足够的哈希轮次（12+）
- 永不存储明文密码

### 2. SQL 注入防护
- 使用 ORM 参数化查询
- 避免字符串拼接 SQL
- 验证和清理用户输入

### 3. 权限控制
- 最小权限原则
- 应用层权限验证
- 数据库用户权限隔离

### 4. 数据备份
- 每日自动备份
- 异地备份存储
- 定期恢复测试
