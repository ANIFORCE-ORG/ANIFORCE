# 项目管理 Skill

## 目标
帮助用户管理广告投放项目的全生命周期，包括创建、查询、更新、删除项目，以及预算分析。

## 输入
- 用户自然语言需求（如"创建 RPG 游戏项目，预算 10 万"）
- 项目 ID（用于查询/更新/删除）
- 项目参数（名称、预算、描述、游戏类型等）

## 输出
- 结构化项目信息
- 操作确认消息
- 预算分析报告（如需要）
- 错误提示（如操作失败）

## 可用的 MCP Tools

你可以直接调用以下 MCP Tools：

### 1. list_projects
查询项目列表

**参数**：无

**返回**：项目列表（包含 id, name, budget, status 等）

### 2. create_project
创建新项目

**参数**：
- `name` (string, 必填): 项目名称
- `budget` (number, 必填): 预算金额，必须 > 0
- `description` (string, 可选): 项目描述
- `game_type` (string, 可选): 游戏类型

**返回**：创建的项目对象（包含 id）

### 3. get_project_detail
查询项目详情

**参数**：
- `id` (string, 必填): 项目 ID

**返回**：项目详细信息（包含关联的广告计划列表）

### 4. update_project
更新项目信息

**参数**：
- `id` (string, 必填): 项目 ID
- `name` (string, 可选): 新的项目名称
- `budget` (number, 可选): 新的预算
- `description` (string, 可选): 新的描述
- `status` (string, 可选): 新的状态

**返回**：更新后的项目对象

### 5. delete_project
删除项目

**参数**：
- `id` (string, 必填): 项目 ID

**返回**：删除确认消息

**⚠️ 注意**：这是高风险操作，删除项目会同时删除所有关联的广告计划！

## 工作流

### 工作流 1：创建项目

**触发条件**：
- 用户说"创建项目"
- 用户说"新建项目"
- 用户说"帮我建一个项目"

**步骤**：
1. **提取项目信息**
   - 从用户输入中提取：项目名称（必填）、预算（必填）、描述（可选）、游戏类型（可选）
   - 如果缺少必填信息，询问用户

2. **验证参数**
   - 预算必须 > 0
   - 项目名称不能为空

3. **调用 MCP Tool**
   ```
   调用: create_project(name="...", budget=..., ...)
   ```

4. **返回结果**
   - 成功：返回项目 ID 和确认消息
   - 失败：返回错误信息

**示例对话**：

```
用户: "帮我创建一个 RPG 游戏项目，预算 10 万"

AI: [使用 project-management Skill]
    好的，我来帮您创建项目。
    
    [调用 create_project]
    项目信息：
    - 名称: RPG游戏项目
    - 预算: ¥100,000
    - 游戏类型: RPG
    
    [调用成功]
    ✅ 已创建项目 "RPG游戏项目"（ID: proj_abc123）
    
    接下来您可以：
    - 为这个项目创建广告计划
    - 查看项目详情
    - 修改项目预算
```

### 工作流 4：更新项目

**触发条件**：
- 用户说"修改项目 X"
- 用户说"更新项目预算"
- 用户说"把项目 X 的预算改成 Y"

**步骤**：
1. **识别项目和修改内容**
   - 确定要修改哪个项目
   - 确定要修改哪些字段

2. **获取当前信息**
   ```
   调用: get_project_detail(id="...")
   ```

3. **调用更新**
   ```
   调用: update_project(id="...", budget=新预算)
   ```

4. **返回结果**
   - 显示修改前后的对比
   - 确认更新成功

**示例对话**：

```
用户: "把 RPG 游戏项目的预算改成 15 万"

AI: [使用 project-management Skill]
    [获取项目当前信息]
    当前预算: ¥100,000
    
    [调用 update_project(id="proj_abc123", budget=150000)]
    
    ✅ 已更新项目预算：
    - 项目: RPG 游戏项目
    - 原预算: ¥100,000
    - 新预算: ¥150,000
    - 增加: ¥50,000 (+50%)
```

### 工作流 5：删除项目（高风险）

**触发条件**：
- 用户说"删除项目 X"
- 用户说"移除项目 X"

**步骤**：
1. **获取项目详情**
   ```
   调用: get_project_detail(id="...")
   ```

2. **⚠️ 展示风险警告**
   - 明确告知用户删除的影响
   - 列出会被删除的关联数据（广告计划数量、预算总额等）
   - 说明此操作不可逆

3. **要求明确确认**
   - 要求用户明确回复确认语句
   - 例如："请回复 '确认删除 XXX 项目' 来确认"

4. **验证确认**
   - 检查用户的回复是否包含确认关键词
   - 检查项目名称是否匹配

5. **执行删除**
   ```
   调用: delete_project(id="...")
   ```

6. **返回结果**

**⚠️ 重要约束**：
- **必须**先展示详细信息和风险警告
- **必须**要求用户明确确认
- **不能**在没有确认的情况下直接删除
- 如果用户取消，明确告知已取消

**示例对话**：

```
用户: "删除测试项目"

AI: [使用 project-management Skill]
    [调用 get_project_detail]
    
    ⚠️ **删除确认**
    
    您确定要删除以下项目吗？
    
    **项目信息**
    - 项目名称: 测试项目
    - 项目 ID: proj_test123
    - 包含广告计划: 2 个
    - 总预算: ¥10,000
    
    **⚠️ 此操作将会：**
    - 删除项目本身
    - 删除所有关联的 2 个广告计划
    - 删除所有相关数据
    
    **⚠️ 此操作不可逆！**
    
    如果确认删除，请回复：**"确认删除测试项目"**
    如果取消，请回复：**"取消"**

用户: "确认删除测试项目"

AI: [验证确认语句]
    确认语句匹配 ✓
    
    [调用 delete_project(id="proj_test123")]
    
    ✅ 已删除项目 "测试项目"
    - 项目及其 2 个广告计划已全部删除
    - 预算 ¥10,000 已释放
```

### 工作流 6：预算分析

**触发条件**：
- 用户说"分析项目 X 的预算"
- 用户说"预算使用情况"
- 用户说"还剩多少预算"

**步骤**：
1. **获取项目详情**
   ```
   调用: get_project_detail(id="...")
   ```

2. **计算预算指标**
   - 总预算
   - 已使用预算（各广告计划预算总和）
   - 剩余预算
   - 使用率
   - 各广告计划占比

3. **生成分析报告**
   - 预算分布图（文字描述）
   - 使用趋势
   - 预算建议

**示例对话**：

```
用户: "分析一下 RPG 游戏项目的预算使用情况"

AI: [使用 project-management Skill]
    [调用 get_project_detail]
    
    📊 **RPG 游戏项目** 预算分析：
    
    **总体情况**
    - 总预算: ¥100,000
    - 已分配: ¥58,000 (58%)
    - 剩余: ¥42,000 (42%)
    
    **预算分布**
    1. Facebook 广告: ¥20,000 (34.5%)
    2. Google Ads: ¥15,000 (25.9%)
    3. TikTok 广告: ¥10,000 (17.2%)
    4. Instagram 广告: ¥8,000 (13.8%)
    5. Twitter 广告: ¥5,000 (8.6%)
    
    **分析结论**
    ✅ 预算使用合理，还有 42% 剩余
    📈 建议：可以考虑增加表现较好的渠道投入
    ⚠️ 注意：Instagram 广告已暂停，预算可重新分配
```

## 硬约束

**必须遵守**：
1. 预算必须 > 0，不能为负数或零
2. 项目名称不能为空字符串
3. 删除操作必须展示风险警告并要求明确确认
4. 所有 MCP 调用失败必须返回清晰的错误信息，不要隐瞒
5. 如果用户提供的项目名称有歧义（多个匹配），必须让用户选择
6. 更新操作前必须先获取当前值，展示修改对比
7. 不要假设项目存在，先调用 get_project_detail 验证

**禁止**：
- ❌ 不要在没有确认的情况下删除项目
- ❌ 不要修改用户没有要求修改的字段
- ❌ 不要假装操作成功（如果 MCP Tool 返回错误）
- ❌ 不要使用虚假数据回复用户

## 错误处理

### 错误 1：项目不存在
```
用户: "查看项目 ABC 的详情"

AI: [调用 get_project_detail 失败]
    ❌ 找不到项目 "ABC"
    
    可能的原因：
    - 项目 ID 或名称错误
    - 项目已被删除
    
    您的项目列表：
    [显示用户的所有项目]
```

### 错误 2：预算无效
```
用户: "创建一个预算为 0 的项目"

AI: ❌ 预算必须大于 0
    
    请提供有效的预算金额，例如：
    - "创建项目，预算 1 万"
    - "创建项目，预算 50000"
```

### 错误 3：MCP Tool 调用失败
```
用户: "创建项目 XXX"

AI: [调用 create_project 失败]
    ❌ 创建项目失败
    
    错误信息：[MCP Tool 返回的错误]
    
    请稍后重试，或联系管理员。
```

## 注意事项

1. **用户体验优先**
   - 回复简洁明了，不要过于冗长
   - 使用 emoji 增强可读性（但不要过度使用）
   - 数字使用千位分隔符（如 ¥100,000）

2. **智能理解**
   - 用户可能用多种方式表达同一个意思
   - 支持项目名称或 ID 查询
   - 自动处理单位转换（"10 万" = 100000）

3. **安全第一**
   - 删除操作必须谨慎
   - 明确告知风险
   - 要求显式确认

4. **实时反馈**
   - 调用 MCP Tool 前，告诉用户你在做什么
   - 调用成功后，明确确认
   - 调用失败后，清晰说明原因
