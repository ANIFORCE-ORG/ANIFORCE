# 人机协作 Skill (HITL Operations)

## 目标
为高风险操作提供人机协作流程，确保用户在充分了解风险的情况下做出决策。

## 什么是 HITL？

**Human-in-the-Loop（人机协作）**：Agent 在执行关键操作前暂停，向用户展示详细信息和风险警告，等待用户明确确认后再执行。

**核心价值**：
- 🛡️ **安全保障**：防止误操作
- ✋ **用户控制**：用户始终掌握主导权
- 👁️ **透明可控**：用户清楚 AI 要做什么

---

## 适用场景

### 需要 HITL 的操作

| 操作类型 | 风险等级 | 是否需要 HITL | 原因 |
|---------|---------|-------------|------|
| 查询项目/广告 | 低 | ❌ | 只读操作，无风险 |
| 创建项目/广告 | 低-中 | ⚠️ 可选 | 可撤销，建议预览 |
| 更新预算（单个） | 中 | ⚠️ 建议 | 可能影响投放，建议对比 |
| 更新预算（批量） | 高 | ✅ **必须** | 影响多个对象 |
| 删除项目 | 高 | ✅ **必须** | 不可逆，影响关联数据 |
| 删除广告计划 | 中-高 | ✅ **必须** | 不可逆 |
| 批量删除 | 高 | ✅ **必须** | 不可逆，影响范围大 |
| 暂停/启动广告 | 中 | ⚠️ 建议 | 影响投放 |
| 批量暂停/启动 | 高 | ✅ **必须** | 影响多个广告 |

## 当前实现方式（Block 6 之前）

**⚠️ 注意**：完整的 HITL 系统将在 **Block 6** 实现（带弹窗确认）。

**当前版本的权宜之计**：
1. **展示详细信息和风险警告**
2. **明确告知风险和影响范围**
3. **要求用户通过对话明确确认**
4. **验证用户回复包含确认关键词**
5. **执行操作并反馈结果**

## 工作流

### 工作流 1：删除单个对象（项目或广告计划）

**触发条件**：
- 用户说"删除项目 X"
- 用户说"删除广告计划 Y"

**步骤**：

1. **获取对象详情**
   ```
   调用: get_project_detail(id="...") 或 get_campaign_detail(id="...")
   ```

2. **评估风险和影响范围**
   - 如果是项目：统计包含多少广告计划
   - 如果是广告计划：评估是否正在投放
   - 计算涉及的预算金额

3. **生成风险警告**
   - 使用醒目的 emoji（⚠️ 🚨）
   - 列出所有会被影响的数据
   - 明确说明"此操作不可逆"

4. **要求明确确认**
   - 提供明确的确认语句模板
   - 例如："请回复 '确认删除 XXX' 来确认"
   - 同时提供取消选项

5. **等待用户回复**
   - 检查用户下一条消息

6. **验证确认**
   - 检查是否包含"确认"关键词
   - 检查是否包含对象名称
   - 如果不匹配，要求重新确认

7. **执行操作**
   ```
   调用: delete_project(id="...") 或 delete_campaign(id="...")
   ```

8. **反馈结果**
   - 确认删除成功
   - 说明已删除的内容

**示例对话**：

```
用户: "删除测试项目"

AI: [使用 hitl-operations Skill]
    [调用 get_project_detail(id="proj_test")]
    
    ⚠️ **删除确认** ⚠️
    
    您确定要删除以下项目吗？
    
    **项目信息**
    - 项目名称: 测试项目
    - 项目 ID: proj_test123
    - 创建时间: 2025-06-12
    - 当前状态: 进行中
    
    **影响范围**
    - 包含广告计划: 2 个
      1. Facebook 测试广告 - ¥5,000 - 进行中
      2. Google 测试广告 - ¥3,000 - 已暂停
    - 涉及总预算: ¥10,000
    
    **⚠️ 此操作将会：**
    - ❌ 删除项目本身
    - ❌ 删除所有 2 个关联的广告计划
    - ❌ 删除所有相关数据和设置
    
    **🚨 此操作不可逆！数据删除后无法恢复！**
    
    ---
    
    如果确认删除，请回复：**"确认删除测试项目"**
    如果取消，请回复：**"取消"**

用户: "确认删除测试项目"

AI: [验证确认语句]
    ✅ 确认语句匹配
    ✅ 项目名称匹配
    
    [调用 delete_project(id="proj_test123")]
    
    ✅ **删除成功**
    
    已删除：
    - 项目: 测试项目 (proj_test123)
    - 广告计划: 2 个
      1. Facebook 测试广告
      2. Google 测试广告
    - 释放预算: ¥10,000
    
    删除操作已完成。
```

### 工作流 2：批量删除

**触发条件**：
- 用户说"删除所有测试项目"
- 用户说"删除项目 A、B、C"
- 用户说"批量删除"

**步骤**：

1. **识别要删除的对象列表**
   - 通过名称、标签或条件筛选

2. **获取所有对象的详情**
   ```
   对每个对象: get_project_detail(id="...")
   ```

3. **汇总影响范围**
   - 总数量
   - 涉及的关联数据数量
   - 涉及的总预算

4. **生成批量删除警告**
   - 列出所有将被删除的对象
   - 显示汇总统计
   - 特别强调"批量操作"的风险

5. **要求明确确认**
   - 确认语句中包含数量
   - 例如："确认批量删除 3 个项目"

6. **验证并执行**
   ```
   对每个对象: delete_project(id="...")
   ```

7. **反馈批量操作结果**
   - 成功数量
   - 失败数量（如有）
   - 详细列表

**示例对话**：

```
用户: "删除所有名称包含'测试'的项目"

AI: [使用 hitl-operations Skill]
    [调用 list_projects 并筛选]
    [对每个项目调用 get_project_detail]

    **汇总统计**

    - ❌ 删除所有相关数据
    
    **🚨 此操作不可逆！批量删除风险极高！**
    
    ---
    
    如果确认删除，请回复：**"确认批量删除 3 个项目"**
    如果取消，请回复：**"取消"**

用户: "确认批量删除 3 个项目"

AI: [验证确认语句]
    ✅ 确认语句匹配
    ✅ 数量匹配 (3)

### 工作流 3：批量修改

**触发条件**：
- 用户说"把所有广告的预算都改成 X"
- 用户说"批量修改"
- 用户说"暂停所有广告"

**步骤**：

1. **识别要修改的对象和修改内容**

2. **获取所有对象的当前值**

3. **生成预览表格**
   - 显示修改前后的对比
   - 使用表格清晰展示

4. **要求确认**

5. **执行批量修改**

6. **反馈结果**

**示例对话**：

```
用户: "把项目 A 的所有广告计划预算都改成 1 万"

AI: [使用 hitl-operations Skill]
    [调用 list_campaigns(project_id="proj_a")]
    [获取每个广告计划的当前预算]
    
    ⚠️ **批量修改确认**
    
    您确定要批量修改以下 5 个广告计划的预算吗？
    
    **修改预览**
    
    | 广告计划 | 原预算 | 新预算 | 变化 |

    | Facebook 广告 | ¥20,000 | ¥10,000 | -¥10,000 (-50%) |

    如果确认修改，请回复：**"确认批量修改预算"**
    如果取消，请回复：**"取消"**

## 硬约束

**必须遵守**：

1. **风险评估**
   - 必须准确评估操作的风险等级
   - 高风险操作必须使用 HITL

2. **信息透明**
   - 必须展示完整的影响范围
   - 不能隐瞒任何会被影响的数据
   - 必须明确说明"不可逆"

3. **确认机制**
   - 必须要求明确的确认语句
   - 确认语句必须包含关键信息（对象名称、数量等）
   - 不能接受模糊的确认（如"好的"、"是的"）

4. **用户控制**
   - 必须提供取消选项
   - 用户取消后立即停止，不执行任何操作
   - 取消后要明确告知用户

5. **操作反馈**
   - 批量操作要显示进度
   - 操作完成后要提供详细汇总
   - 失败要说明原因

**禁止**：
- ❌ 不能在没有确认的情况下执行高风险操作
- ❌ 不能隐瞒风险
- ❌ 不能接受模糊的确认
- ❌ 不能忽略用户的取消请求

## 注意事项

1. **确认语句设计**
   - 包含对象名称（防止误操作）
   - 包含数量（批量操作）
   - 使用明确的动词（"确认删除"而不是"好的"）

2. **风险分级**
   - 低风险：无需确认
   - 中风险：建议确认（可选）
   - 高风险：必须确认

3. **批量操作**
   - 特别强调"批量"
   - 显示完整列表
   - 显示汇总统计

4. **用户教育**
   - 首次使用时解释为什么需要确认
   - 说明 HITL 是为了保护用户数据
