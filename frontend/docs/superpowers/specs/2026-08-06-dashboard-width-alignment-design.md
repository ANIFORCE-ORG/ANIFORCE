# Dashboard 宽度与视觉密度对齐设计

## 目标

将本地数据复盘页在高分屏、超宽视口下的视觉比例对齐参考图：避免内容横向拉伸造成卡片和图表“被压扁”，同时保持现有文字、数据、色彩、交互与业务逻辑不变。

## 已确认根因

参考图视口为 1288 × 1280；本地截图为 3180 × 3004，高分屏下对应的 CSS 视口更宽。当前 `.replay-content` 允许扩展至 1500px，但字号、卡片高度与图表高度采用固定像素值。横向尺寸继续增加、纵向尺寸不变，导致宽高比例失衡。

## 设计方案

采用居中的 Notion 式内容画布：

- Dashboard 主内容区最大宽度设为 1080px，宽度不足时仍保持 100% 自适应。
- 顶部标题、筛选器与主内容区对齐到同一条 1080px 内容网格，同时保留整行底部分隔线。
- 通过响应式水平内边距计算实现对齐，不增加额外 DOM，不改变组件层级。
- 桌面端继续保持平台卡片一行 3 个；现有 1220px、900px、620px 响应式断点保持不变。
- 不使用 `zoom` 或 `transform: scale()`，避免字体模糊、滚动范围错误和弹窗定位偏移。

## 代码范围

仅修改 `packages/main-app/src/pages/Dashboard.vue` 的 scoped CSS：

1. 将 `.replay-content` 的 `max-width` 从 1500px 调整为 1080px，并保持水平居中。
2. 将 `.replay-bar` 的水平内边距改为基于 1080px 内容网格计算的响应式值。
3. 不修改模板、脚本、数据结构、事件处理及其他页面。

## 验收标准

- 在约 1288px CSS 宽度下，页面布局与参考图保持一致。
- 在约 1590px CSS 宽度及更宽屏幕下，内容宽度不再继续横向拉伸，卡片与图表比例保持稳定。
- 桌面端平台卡片仍为一行 3 个。
- 1220px 以下的既有响应式布局不回归。
- 项目构建通过，CSS 无语法错误，登录旁路的现有未提交改动不被覆盖。
