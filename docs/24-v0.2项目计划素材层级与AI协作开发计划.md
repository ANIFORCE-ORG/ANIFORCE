# v0.2 项目-计划-素材层级与 AI 协作开发计划

## 1. 背景

依据 `/Users/PJlai/Desktop/DEV Doc/chen design/0512preview (30).html` 的原型评估，当前系统已有“项目 -> Campaign/计划 -> 素材”的基础关系，但原型强调更清晰的业务层级和创建任务流程：

1. 项目是上层业务容器，承载客户、产品、目标市场、预算、周期和负责人。
2. 广告计划是项目下的二级执行对象，承接项目预算、渠道、账户、转化目标、投放时间和素材配置。
3. 素材挂在计划下，且同一素材在不同计划中可能有不同标题、描述和投放文案。
4. 创建计划应从项目入口出发，经过信息校验、素材选择、最终确认和批量创建。
5. 任务查看要能在项目详情中查看计划列表、计划详情、计划素材和复盘建议。
6. AI 只负责抽取、生成、解释和建议；系统负责校验、落库、创建和执行。

本计划延续：

- `docs/10-2026-05-11客户第一版交付计划.md`
- `docs/11-2026-05-11多Agent协作执行规程.md`
- `docs/23-客户交付业务全链路测试记录.md`

执行原则：

1. 采用多 Agent 并行协作方式开发。
2. 以实际交付业务流程进行测试。
3. 以交付给客户的标准完成开发。
4. 非必要不中断连续开发；每天完成当天任务后记录总结并继续下一天。

## 2. v0.2 目标

交付一条可上线演示、可客户试用、可继续扩展的主链路：

```text
客户确认合作
  -> 系统账号交付
  -> 创建/确认项目
  -> 绑定投放账户
  -> 从项目下创建计划
  -> 选择/上传素材并生成标题描述
  -> 确认计划数量和命名规则
  -> 创建计划
  -> 上传/同步投放结果
  -> Agent 复盘建议
  -> 人工确认/拒绝建议
  -> 形成客户复盘记录
```

核心变化：

- 从“独立 Campaign 创建页”升级为“项目详情内向下创建计划”。
- 从“Campaign 仅保存 material_ids”升级为“计划-素材绑定关系带标题和描述”。
- 从“右侧助手泛聊”升级为“受控 AI Gateway：场景白名单、Schema 输出、Token 成本记录、人工确认”。
- 从“功能级测试”升级为“业务交付端到端测试”。

## 3. 产品范围

### 3.1 P0 必须交付

1. 项目详情成为主入口：
   - 项目概览。
   - 项目下计划列表。
   - 计划详情。
   - 从项目向下新建计划。
   - 从计划复制创建。

2. 计划创建流程：
   - Step 1：任务信息校验。
   - Step 2：素材选择/上传/无素材，并填写素材标题和描述。
   - Step 3：计划数量、命名规则、项目归属、素材覆盖、预算策略确认。
   - 支持 0-99 个计划批量创建。

3. 计划-素材绑定元数据：
   - 一个素材在不同计划下可有不同标题和描述。
   - CampaignDetail 展示计划素材标题、描述、素材来源和状态。

4. AI Gateway：
   - 统一模型调用入口。
   - 场景白名单。
   - JSON Schema 输出约束。
   - Token/成本记录。
   - AI 输出均为草稿或建议，不直接执行真实投放动作。

5. 业务全链路测试：
   - 登录账号。
   - 创建项目。
   - 绑定投放账户。
   - 上传素材。
   - 创建计划。
   - 上传投放结果。
   - 复盘建议。
   - 确认/拒绝建议。

### 3.2 P1 尽量交付

- 首页或右侧助手自然语言触发创建计划。
- 自动匹配项目。
- 素材推荐。
- 素材标题/描述生成 3 个候选。
- 复制计划直接进入第三步确认。
- AI 使用量后台看板。
- 重复请求缓存，降低 Token 消耗。

### 3.3 暂不纳入

- AI 自动执行预算调整。
- 自动调用 Meta 修改真实 Campaign。
- Google/TikTok 真实投放链路。
- 多客户账单系统。
- 完整对象存储迁移。

### 4.3 创建计划流程

入口：

- 项目详情：`+ 新建广告/计划`
- 计划详情：`复制当前计划`
- ChatPanel：自然语言创建计划，P1

Step 1：任务信息校验

字段：

- 项目归属。
- 投放国家/地区。
- 渠道。
- 渠道账户/API。
- 投放产品。
- 预算。
- 成本目标。
- 转化目标。
- 投放时间段。

校验原则：

- AI 可抽取字段。
- 系统规则决定通过与否。
- 未通过字段必须停留在当前步骤。
- 账户、预算、项目权限必须以后端为准。

Step 2：素材选择

模式：

- 素材库选择。
- 本地上传。
- 无须素材。

约束：

- 每个计划默认 1-9 个素材。
- 每个素材绑定时必须有标题和描述。
- AI 可生成素材标题/描述候选。
- 人工确认后才进入第三步。

Step 3：创建确认

确认项：

- 项目归属。
- 计划数量：0-99。
- 命名规则。
- 渠道和账户。
- 预算总额。
- 素材覆盖。
- 风险提示。

提交：

- 调用后端批量创建接口。
- 创建后返回任务卡片。
- 可点击进入项目详情下的计划详情。

## 6. 大模型 API 交互设计

### 6.1 统一 AI Gateway

前端禁止直连模型 API。

架构：

```text
Frontend
  -> Backend AI Gateway
    -> 场景权限校验
    -> 上下文裁剪
    -> Prompt 模板
    -> Token 预估
    -> 成本预算检查
    -> Model API
    -> JSON Schema 校验
    -> 业务规则二次校验
    -> 结果落库
    -> Token/Cost 记录
```

新增模块：

```text
backend/app/api/v1/ai_gateway.py
backend/app/services/ai_gateway_service.py
backend/app/services/prompt_template_service.py
backend/app/services/token_budget_service.py
backend/app/schemas/ai.py
backend/app/models/ai_usage.py
```

### 6.2 AI 场景白名单

| 场景 | 用途 | 是否可写业务数据 |
|---|---|---|
| `project_draft` | 客户沟通后生成项目草稿 | 否 |
| `plan_extract` | 计划信息抽取和字段校验建议 | 否 |
| `material_recommend` | 从素材库推荐素材 | 否 |
| `material_copy` | 生成素材标题和描述 | 否 |
| `plan_review` | 创建前配置检查 | 否 |
| `campaign_diagnosis` | 投放中异常诊断 | 只写 Agent 建议 |
| `report_summary` | 结果复盘摘要 | 只写报告草稿 |
| `chat_general` | 右侧助手普通问答 | 否 |

### 6.3 Token 与成本控制

每个场景固定输入输出上限：

| 场景 | 输入上限 | 输出上限 | 默认模型 |
|---|---:|---:|---|
| `plan_extract` | 4k | 1.2k | small/medium |
| `material_copy` | 3k | 1k | small |
| `material_recommend` | 8k | 1.5k | medium |
| `campaign_diagnosis` | 8k | 1.5k | medium |
| `report_summary` | 12k | 2k | medium/large |
| `chat_general` | 4k | 800 | small |

调用前必须：

1. 校验场景是否允许。
2. 校验用户是否能访问项目、计划、素材。
3. 裁剪上下文。
4. 预估 Token。
5. 检查日/月预算。
6. 设置 `max_output_tokens`。
7. 调用模型。
8. 记录实际 Token 和成本。
9. 校验 JSON Schema。
10. 保存 AI 输出。

环境变量：

```env
AI_PROVIDER=openai
OPENAI_API_KEY=
AI_DEFAULT_MODEL=
AI_SMALL_MODEL=
AI_MEDIUM_MODEL=
AI_LARGE_MODEL=
AI_DAILY_COST_LIMIT_USD=20
AI_MONTHLY_COST_LIMIT_USD=500
AI_LOG_PROMPTS=false
AI_LOG_OUTPUTS=true
```

### 6.4 输出约束

所有 AI 输出必须是 JSON，不允许自由文本直接进入业务执行。

计划抽取输出：

```json
{
  "project_match": {
    "project_id": "string|null",
    "confidence": 0.0
  },
  "fields": {
    "country": { "value": "US", "status": "pass", "reason": "用户明确提到美国" },
    "channel": { "value": "Meta", "status": "pass", "reason": "用户明确提到 Meta" },
    "budget": { "value": 800, "currency": "USD", "period": "daily", "status": "pass" }
  },
  "missing_fields": [],
  "blocking_issues": [],
  "next_question": "string|null"
}
```

素材文案输出：

```json
{
  "material_id": "mat_001",
  "candidates": [
    {
      "title": "短剧反转高能开场",
      "description": "面向北美女性用户，突出剧情冲突和追剧爽点。",
      "risk_flags": []
    }
  ]
}
```

复盘输出：

```json
{
  "facts": {
    "campaign_id": "camp_001",
    "spend": 7600,
    "installs": 310,
    "cpi": 24.52,
    "roi": 1.53
  },
  "findings": [
    {
      "level": "warning",
      "title": "CPI 高于目标",
      "evidence": "latest_cpi=24.52,target_cpa=20"
    }
  ],
  "recommendations": [
    {
      "action_type": "review_cpi",
      "summary": "建议收窄定向或替换疲劳素材",
      "requires_human_confirm": true
    }
  ]
}
```

强约束：

- AI 不能编造项目、账户、Campaign、素材 ID。
- AI 不能直接调用 Meta API。
- AI 不能直接创建真实投放。
- AI 不能突破预算校验。
- AI 建议必须进入 `draft/suggested` 状态。
- 所有真实动作必须人工确认。

## 7. 多 Agent 并行协作计划

### 7.1 角色分工

项目经理 Agent：

- 每天恢复上下文。
- 拆 P0/P1。
- 控制范围。
- 更新当日记录。

产品经理 Agent：

- 维护业务验收口径。
- 对齐 HTML 原型层级。
- 明确客户交付表达。

前端工程 Agent：

- ProjectDetail 层级改造。
- CreateCampaign 三步/三段式流程。
- 素材文案编辑。
- 计划详情和任务卡片。

后端工程 Agent：

- 批量创建计划。
- Campaign-Material 绑定表。
- 指标上传。
- Agent Action 状态。

AI 工程 Agent：

- AI Gateway。
- Prompt 模板。
- JSON Schema。
- Token 预算。
- Usage log。

API 集成 Agent：

- 前后端字段对齐。
- 端到端链路接口联调。
- 兼容旧接口。

数据库与部署 Agent：

- Alembic migration。
- SQLite/PG 兼容。
- 演示数据重置。
- 部署配置。

测试工程 Agent：

- 构建。
- 后端编译。
- API 冒烟。
- 业务全链路测试。
- 浏览器页面验收。

发布与交付 Agent：

- 演示脚本。
- 运维手册。
- 已知限制。
- 客户交付清单。

### 7.2 并行开发原则

- 前端、后端、AI Gateway、数据库 migration 可并行。
- 后端 API contract 先冻结，再让前端接入。
- 数据库 migration 不与业务 UI 改动耦合。
- 每天至少跑一次：
  - `pnpm run build`
  - `python3 -m compileall backend/app`
  - 核心 API 冒烟
  - 一条业务链路测试

## 9. 测试策略

### 9.1 业务全链路测试

每轮开发必须按真实交付流程测：

1. 登录账号。
2. 创建客户项目。
3. 绑定 Meta 投放账户。
4. 上传真实广告素材文件。
5. 从项目详情创建计划。
6. 选择素材并填写标题/描述。
7. 批量创建计划。
8. 查看项目计划列表。
9. 查看计划详情。
10. 上传投放结果。
11. 生成 Agent 建议。
12. 确认/拒绝建议。
13. 输出复盘记录。

### 9.2 技术验证

每天至少执行：

```bash
pnpm run build
python3 -m compileall backend/app
GET /health
GET /api/v1/projects
GET /api/v1/campaigns
GET /api/v1/materials
GET /api/v1/platform/accounts
```

AI Gateway 验证：

- 正常场景输出。
- Schema 错误处理。
- Token 超限处理。
- 模型 API 失败处理。
- Usage log 落库。

## 10. 交付标准

交付给客户前必须满足：

- 可部署。
- 可登录。
- 可绑定投放账户。
- 可创建项目。
- 可从项目创建计划。
- 可上传素材。
- 可绑定素材并保存标题/描述。
- 可上传/同步投放结果。
- 可生成复盘建议。
- 可人工确认/拒绝建议。
- AI 调用可审计、可限额、可追踪。
- 构建和后端编译通过。
- 演示脚本和已知限制完整。

## 11. 当前风险

| 风险 | 等级 | 处理 |
|---|---|---|
| 计划-素材元数据需要 migration | 高 | Day 2 优先完成 |
| 前端创建流程重构范围较大 | 高 | 保留旧路由兼容，逐步替换 |
| AI Gateway 依赖模型密钥和成本配置 | 高 | 支持 Mock Provider 和真实 Provider 双模式 |
| Token 成本不可控 | 高 | 场景上限、预算表、Usage log |
| 客户误解 AI 可自动执行投放 | 中 | 所有 AI 输出标记为建议，真实动作人工确认 |
| 本地 socket 偶发受限 | 中 | 以构建/API/浏览器验收综合判断 |
