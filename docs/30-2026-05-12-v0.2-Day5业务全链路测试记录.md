## 发现并修复的断点

### 断点 1：指标上传允许消耗超过计划预算

现象：

- 上传 `spend=1800` 到预算 `100` 的计划时，接口接受了数据。
- Agent 建议生成 `usage_rate=18.0`，不符合客户交付数据可信度。

修复：

- 在 `POST /api/v1/campaigns/{campaign_id}/metrics` 增加预算校验。
- 如果 `spend > campaign.budget`，返回 422。

复测：

- 合法数据 `spend=90` 上传成功。
- 非法数据 `spend=1800` 返回：

```json
{"detail":"投放消耗不能超过计划预算，当前计划预算为 100.00"}
```

### 断点 2：异常测试数据污染 Agent 建议

现象：

- 修复前生成过一条异常 Agent 建议。

处理：

- 重新上传合法时间更晚的指标。
- 重新生成 Agent 建议，当前 suggested 建议已恢复为 `usage_rate=0.9`。
