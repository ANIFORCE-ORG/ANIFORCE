### 1.2 三层解耦架构

整体采用 **数据层 → 后端层 → 前端层** 严格解耦设计，每一层通过明确的接口契约通信，互不感知内部实现。

```
┌─────────────────────────────────────────────────────────────────────┐
│                         前端层 (Presentation)                        │
│                                                                     │
│  ┌─────────────┐   ┌──────────────┐   ┌──────────────────────────┐ │
│  │  UI 组件     │ → │ 状态管理      │ → │ 数据访问层 (DAL)          │ │
│  │  (Vue/React) │   │ (Pinia/      │   │ - ApiClient 抽象接口     │ │
│  │              │   │  Zustand)    │   │ - MockClient (Demo)      │ │
│  │              │   │              │   │ - HttpClient (生产)       │ │
│  └─────────────┘   └──────────────┘   └───────────┬──────────────┘ │
└───────────────────────────────────────────────────┼────────────────┘
                                                    │ HTTP / WebSocket
                                                    │ (RESTful API 契约)
┌───────────────────────────────────────────────────┼────────────────┐
│                         后端层 (Application)       │                │
│                                                    ↓                │
│  ┌──────────────┐   ┌──────────────┐   ┌──────────────────────┐   │
│  │ API 路由层    │ → │ Service 层    │ → │ Repository 协议层     │   │
│  │ (FastAPI     │   │ (业务逻辑,    │   │ (Protocol/ABC 抽象,  │   │
│  │  Router)     │   │  不感知存储)  │   │  依赖注入切换实现)    │   │
│  └──────────────┘   └──────────────┘   └───────────┬──────────┘   │
└───────────────────────────────────────────────────┼───────────────┘
                                                    │ Repository 接口
                                                    │ (数据访问契约)
┌───────────────────────────────────────────────────┼───────────────┐
│                         数据层 (Data)              │                │
│                                                    ↓                │
│  ┌──────────────┐  ┌──────────┐  ┌──────────┐  ┌──────────────┐  │
│  │ PostgreSQL   │  │ MongoDB  │  │ Redis    │  │ ClickHouse   │  │
│  │ (SQLAlchemy  │  │ (Motor   │  │ (缓存/   │  │ (OLAP        │  │
│  │  实现)       │  │  实现)   │  │  队列)   │  │  实现)       │  │
│  └──────────────┘  └──────────┘  └──────────┘  └──────────────┘  │
│  ┌──────────────────────────────────────────────────────────────┐  │
│  │  MockRepository (Demo 模式，内存数据，无需真实数据库)          │  │
│  └──────────────────────────────────────────────────────────────┘  │
└───────────────────────────────────────────────────────────────────┘
```

**解耦核心原则**：

| 原则 | 说明 | 实现方式 |
|------|------|---------|
| **前端不感知后端实现** | 前端只依赖 API 契约（OpenAPI Schema），不关心后端用 Python/Java/Go | RESTful API + Pydantic Schema 自动生成 OpenAPI |
| **后端不感知存储引擎** | Service 层只依赖 Repository Protocol，不直接导入 SQLAlchemy/Motor | Python Protocol + FastAPI Depends 依赖注入 |
| **数据层可独立替换** | 更换数据库只需实现新的 Repository，不影响 Service 和 API 层 | Repository Pattern + 工厂模式 |
| **Demo 模式零侵入** | Demo/Mock 通过依赖注入替换 Repository 实现，Service 层代码零修改 | MockRepository 注入替换真实 Repository |
| **前端 Mock 独立** | 前端 Demo 模式通过 DAL 层切换 MockClient，不影响 UI 和状态管理 | 数据访问层抽象 + 环境变量切换 |

### 1.3 数据流向

```
[用户操作] → UI 组件 → 状态管理 → DAL (ApiClient)
                                        │
                          ┌──────────────┤
                          │ Demo 模式     │ 生产模式
                          ↓              ↓
                     MockClient     HttpClient → HTTP → FastAPI Router
                     (本地固定数据)                          │
                                                      ↓
                                                  Service 层
                                                  (纯业务逻辑)
                                                      │
                                            ┌─────────┤
                                            │ Demo    │ 生产
                                            ↓         ↓
                                       MockRepo   RealRepo → DB
                                       (内存数据)  (SQLAlchemy/Motor)
```

### 1.4 技术选型原则

1. **成熟稳定**: 选择经过验证的技术栈，FastAPI 已成为 Python Web 框架主流
2. **开发效率**: 微前端允许团队按擅长框架并行开发，Python 生态丰富加速 AI 集成
3. **可扩展性**: 微前端架构支持独立部署和渐进式扩展
4. **性能优先**: FastAPI 基于 ASGI 异步，性能接近 Go/Node.js；前端按需加载子应用
5. **成本可控**: Python 生态降低 AI/ML 集成成本，微前端复用已有组件库
6. **团队适配**: 前端团队可按 React/Vue3 擅长方向分工，降低学习成本
7. **三层解耦**: 数据层、后端层、前端层通过接口契约严格隔离，支持独立演进和替换

## 2. 前端技术栈详解

### 2.1 微前端架构概览

采用 **qiankun** 微前端方案，Vue3 作为主应用（壳工程），React 和 Vue3 分别承担不同子应用模块。

**应用划分**：

| 应用 | 框架 | 职责 | 路由前缀 |
|------|------|------|---------|
| **主应用 (Shell)** | Vue3 | 全局框架、登录、Header、Sidebar、设置、账户管理 | `/` |
| **子应用1 (AI+Monitor)** | React 18 | AI 智能对话页、监控看板页 | `/ai-chat`, `/monitor` |
| **子应用2 (Campaign)** | Vue3 | 素材生成页、投放配置页 | `/material`, `/campaign` |

**选型理由**：
- AI 对话和监控看板涉及大量实时流式渲染、复杂动画，React 生态（Framer Motion、Recharts）更成熟
- 素材生成和投放配置偏表单/配置型页面，Vue3 的响应式系统和模板语法开发效率更高
- 主应用用 Vue3 管理全局状态和布局，与子应用2 共享技术栈，减少重复依赖

#### 2.4.5 WebSocket Hook (React 子应用)

```typescript
// packages/react-app/src/hooks/useWebSocket.ts
import { useEffect, useRef, useState, useCallback } from 'react';

interface UseWebSocketOptions {
  url: string;
  protocols?: string[];
  autoConnect?: boolean;
  reconnectAttempts?: number;
  reconnectInterval?: number;
}

export function useWebSocket(options: UseWebSocketOptions) {
  const {
    url,
    protocols,
    autoConnect = true,
    reconnectAttempts = 5,
    reconnectInterval = 3000,
  } = options;

  const [isConnected, setIsConnected] = useState(false);
  const wsRef = useRef<WebSocket | null>(null);
  const attemptsRef = useRef(0);

  const connect = useCallback(() => {
    const ws = new WebSocket(url, protocols);

    ws.onopen = () => {
      setIsConnected(true);
      attemptsRef.current = 0;
    };

    ws.onclose = () => {
      setIsConnected(false);
      if (attemptsRef.current < reconnectAttempts) {
        attemptsRef.current++;
        setTimeout(connect, reconnectInterval);
      }
    };

    ws.onerror = (err) => console.error('WebSocket error:', err);

    wsRef.current = ws;
  }, [url, protocols, reconnectAttempts, reconnectInterval]);

  useEffect(() => {
    if (autoConnect) connect();
    return () => { wsRef.current?.close(); };
  }, [autoConnect, connect]);

  const send = useCallback((data: string | object) => {
    const payload = typeof data === 'string' ? data : JSON.stringify(data);
    wsRef.current?.send(payload);
  }, []);

  const onMessage = useCallback((handler: (data: any) => void) => {
    if (wsRef.current) {
      wsRef.current.onmessage = (event) => {
        try { handler(JSON.parse(event.data)); }
        catch { handler(event.data); }
      };
    }
  }, []);

  return { isConnected, send, onMessage, ws: wsRef.current };
}
```

## 4. 前后端能力隔离方案

### 4.1 隔离原则

**前端职责（微前端各应用）**：
1. UI 渲染和用户交互（各子应用独立负责）
2. 表单验证（客户端，Zod / VeeValidate）
3. 路由跳转和页面状态（qiankun 路由协调）
4. 本地缓存和临时状态（Zustand / Pinia）
5. 动画和视觉效果（Framer Motion / CSS Transitions）
6. 跨应用状态同步（qiankun GlobalState）

**后端职责（FastAPI）**：
1. 核心业务逻辑（Service 层）
2. 数据验证（Pydantic Schema，服务端强校验）
3. 权限控制和鉴权（JWT + FastAPI Depends）
4. 数据持久化（SQLAlchemy + Motor）
5. 外部 API 集成（httpx 异步调用）
6. 异步任务处理（Celery + Redis）
7. WebSocket 实时推送（FastAPI WebSocket）

### 4.2 后端三层解耦实现 — Repository Pattern + 依赖注入

后端采用 **API 路由层 → Service 层 → Repository 协议层** 严格分层，Service 层只依赖 Repository Protocol（抽象接口），不直接导入任何 ORM 或数据库驱动。

#### 4.2.1 Repository Protocol 定义

```python
# app/repositories/protocols.py
from typing import Protocol, Optional, runtime_checkable
from datetime import datetime

@runtime_checkable
class UserRepository(Protocol):
    """用户数据访问协议 — Service 层只依赖此接口"""
    async def get_by_id(self, user_id: str) -> Optional[dict]: ...
    async def get_by_email(self, email: str) -> Optional[dict]: ...
    async def create(self, email: str, password_hash: str, name: str) -> dict: ...

@runtime_checkable
class ChatRepository(Protocol):
    """对话数据访问协议"""
    async def create_session(self, user_id: str, game_info: dict) -> str: ...
    async def add_message(self, session_id: str, role: str, content: str, metadata: dict = None) -> None: ...
    async def get_session(self, session_id: str) -> Optional[dict]: ...
    async def list_sessions(self, user_id: str, limit: int = 20) -> list[dict]: ...

@runtime_checkable
class CampaignRepository(Protocol):
    """投放数据访问协议"""
    async def create(self, user_id: str, name: str, game_type: str, budget: float, config: dict) -> dict: ...
    async def get_by_id(self, campaign_id: str) -> Optional[dict]: ...
    async def update_status(self, campaign_id: str, status: str) -> None: ...
    async def list_by_user(self, user_id: str) -> list[dict]: ...

@runtime_checkable
class MaterialRepository(Protocol):
```

#### 4.2.2 真实数据库实现（示例：PostgreSQL）

```python
# app/repositories/impl/pg_campaign_repo.py
from sqlalchemy.ext.asyncio import AsyncSession
from sqlalchemy import select
from app.models.campaign import Campaign, CampaignStatus
import uuid

class PgCampaignRepository:
    """PostgreSQL 投放 Repository 实现 — 实现 CampaignRepository Protocol"""

    def __init__(self, session: AsyncSession):
        self._session = session

    async def create(self, user_id: str, name: str, game_type: str, budget: float, config: dict) -> dict:
        campaign = Campaign(
            id=str(uuid.uuid4()), user_id=user_id, name=name,
            game_type=game_type, budget=budget, config=config,
        )
        self._session.add(campaign)
        await self._session.flush()
        return self._to_dict(campaign)

    async def get_by_id(self, campaign_id: str):
        result = await self._session.execute(select(Campaign).where(Campaign.id == campaign_id))
        campaign = result.scalar_one_or_none()
        return self._to_dict(campaign) if campaign else None

    async def update_status(self, campaign_id: str, status: str):
        result = await self._session.execute(select(Campaign).where(Campaign.id == campaign_id))
        campaign = result.scalar_one()
        campaign.status = CampaignStatus(status)

    async def list_by_user(self, user_id: str):
        result = await self._session.execute(
            select(Campaign).where(Campaign.user_id == user_id).order_by(Campaign.created_at.desc())
        )
        return [self._to_dict(c) for c in result.scalars()]

    @staticmethod
    def _to_dict(campaign: Campaign) -> dict:
        return {"id": campaign.id, "name": campaign.name, "status": campaign.status.value, ...}
```

```python
async def get_db() -> AsyncSession:
    async with async_session() as session:
        try:
            yield session
            await session.commit()
        except Exception:
            await session.rollback()
            raise
        finally:
            await session.close()
```

## 7. 实时通信方案

### 7.1 FastAPI WebSocket 架构

采用 FastAPI 原生 WebSocket 支持，通过路径区分不同业务频道：

```python
# app/websocket/manager.py
from fastapi import WebSocket
from typing import Dict, Set
import asyncio
import json

class ConnectionManager:
    """WebSocket 连接管理器"""

    def __init__(self):
        # channel -> set of websockets
        self._channels: Dict[str, Set[WebSocket]] = {}

    async def connect(self, websocket: WebSocket):
        await websocket.accept()

    def disconnect(self, websocket: WebSocket):
        for channel, connections in self._channels.items():
            connections.discard(websocket)

    async def subscribe(self, websocket: WebSocket, channel: str):
        if channel not in self._channels:
            self._channels[channel] = set()
        self._channels[channel].add(websocket)

    async def broadcast(self, channel: str, data: dict):
        """向频道内所有连接推送消息"""
        if channel in self._channels:
            dead = []
            for ws in self._channels[channel]:
                try:
                    await ws.send_json(data)
                except Exception:
                    dead.append(ws)
            for ws in dead:
                self._channels[channel].discard(ws)

manager = ConnectionManager()
```

```typescript
import { ref, watch } from 'vue';

export function useMaterialProgress(jobId: string) {
  const progress = ref(0);
  const stage = ref('');
  const completed = ref(false);

  const { data, status } = useWebSocket(
    `${import.meta.env.VITE_WS_URL}/ws/material/${jobId}`,
    { autoReconnect: true }
  );

    const msg = JSON.parse(raw);

      progress.value = msg.data.progress;
      stage.value = msg.data.stage;

    if (msg.event === 'generation_complete') {
      completed.value = true;
    }
  });

  return { progress, stage, completed, status };
```

## 8. Demo 模式实现

### 8.1 设计原则 — 零侵入切换

Demo 模式的核心设计原则是 **Service 层代码零修改**，完全通过三层解耦的依赖注入机制实现切换：

- **前端**：DAL 工厂根据 `VITE_DEMO_MODE` 注入 MockClient 或 HttpClient（见 2.4.4 节）
- **后端**：Repository 工厂根据 `DEMO_MODE` 注入 MockRepository 或真实 Repository（见 4.2.4 节）
- **Service 层**：无任何 Demo/Mock 判断逻辑，始终通过 Repository Protocol 操作数据

```
                    Demo 模式                          生产模式
                    ─────────                          ─────────
前端 DAL:          MockClient (内存固定数据)            HttpClient → FastAPI
后端 Repository:   MockRepository (内存固定数据)        PgRepo / MongoRepo / ChRepo
后端 Service:      ← 完全相同的代码，零 if/else →
```

### 8.2 固定数据流程

```
用户输入 → 返回固定分析结果 → 选择方向 → 返回固定素材 
→ 配置投放 → 返回固定配置 → 监控数据 → 模拟实时更新
```

### 8.3 双层 Mock 策略

Demo 模式同时在前端和后端实现 Mock，确保即使后端未启动也能完整演示：

**前端 Mock 层**（纯前端演示，无需后端）：
- 通过 `VITE_DEMO_MODE=true` 激活
- DAL 工厂注入 MockClient，UI 和状态管理层代码不变
- 适用于展会、演示等离线场景

**后端 Mock 层**（后端运行但不调用外部 API）：
- 通过 `DEMO_MODE=true` 激活
- Repository 工厂注入 MockRepository，Service 层代码不变
- 适用于开发调试、集成测试
