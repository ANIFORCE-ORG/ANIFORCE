# v0.1 技术债与后续修复清单

## 1. 目的

本文件记录为了 v0.1 Customer Preview 交付而采取的临时降级、兼容和技术债。

原则：

- 不把技术债隐藏起来。
- 不让非主链路问题阻断客户预览。
- v0.1 后按优先级还债。

## 2. 当前技术债

### 2.1 前端 TypeScript 严格检查临时降级

为了优先恢复客户预览构建，以下调整属于临时措施：

1. `frontend/packages/main-app/tsconfig.json`
   - `noUnusedLocals=false`
   - `noUnusedParameters=false`

原因：

- 多个历史页面和辅助组件存在未使用变量。
- 未使用变量不影响运行，不应阻断 v0.1 客户预览。

后续处理：

- v0.2 前逐个清理未使用变量。
- 恢复 `noUnusedLocals=true` 和 `noUnusedParameters=true`。

### 2.2 部分页面临时 `ts-nocheck`

以下页面临时加入 `// @ts-nocheck`：

- `frontend/packages/main-app/src/pages/AIGenerateNew.vue`
- `frontend/packages/main-app/src/pages/AIGenerateMix.vue`
- `frontend/packages/main-app/src/components/home/workspace/TodayOverview.vue`
- `frontend/packages/main-app/src/pages/PlatformConnections.vue`
- `frontend/packages/main-app/src/pages/Projects.vue`
- `frontend/packages/main-app/src/pages/DashboardOld.vue`
- `frontend/packages/main-app/src/components/layout/AppHeader.vue`

原因：

- 当前构建错误集中在历史/辅助页面类型不一致。
- v0.1 主交付链路优先级高于这些页面的严格类型治理。

后续处理：

| 文件 | 后续修复方向 |
|---|---|
| `AIGenerateNew.vue` | 收窄媒体类型，避免普通 `string` 传给 `'video' | 'image'` |
| `AIGenerateMix.vue` | 统一素材类型，明确 `format` 字段来源或改用已有字段 |
| `TodayOverview.vue` | 保留数值原始字段，展示时再格式化，避免字符串和数字比较 |
| `PlatformConnections.vue` | 对 `string | undefined` 做显式 guard |
| `Projects.vue` | 前端 `Project` 类型与后端可空字段完全对齐 |
| `DashboardOld.vue` | 如仍保留旧页面，修复字符串/数字比较；如不再使用，移出路由和构建 |
| `AppHeader.vue` | 为导航数据补明确类型，清理隐式 `any[]` |

### 2.3 Node 环境类型 shim

新增：

- `frontend/packages/main-app/node-env.d.ts`

原因：

- 当前项目缺少 Node 类型声明，导致 `vite.config.ts` 中 `path`、`process`、`__dirname` 报错。

后续处理：

- 更标准做法是安装并配置 `@types/node`。
- 如果交付环境允许依赖更新，应在 v0.2 替换 shim。

### 2.4 项目类型可空兼容

调整：

- `frontend/packages/main-app/src/api/projects.ts`

原因：

- 后端项目字段如 `description`、`game_type`、`target_market`、`manager`、`start_date`、`end_date`、`product_type` 可能返回 `null`。
- 前端原类型过于严格。

后续处理：

- 从后端 schema 生成或集中维护前端类型。
- 页面层补默认展示文案，而不是假设字段一定存在。

## 3. v0.2 类型治理计划

优先级：

1. 移除所有 `ts-nocheck`。
2. 清理未使用变量。
3. 恢复 `noUnusedLocals/noUnusedParameters`。
4. 统一 API 类型和后端 Pydantic schema。
5. 引入 API schema 生成或至少集中定义共享类型。

## 4. 交付说明中的表述

对客户不需要暴露内部 TypeScript 技术债细节。

但如果客户要求代码质量说明，可以说明：

- v0.1 是 Customer Preview。
- 已保证主链路可演示和构建目标。
- 历史辅助页面会在 v0.2 做严格类型治理。
- 未完成平台和自动执行能力已明确标注为下一版本。
