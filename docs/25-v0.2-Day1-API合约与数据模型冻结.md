# v0.2 Day 1 API 合约与数据模型冻结

日期：2026-05-12

## 1. 冻结结论

v0.2 主流程沿用原型的业务层级：

```text
项目 -> 计划 Campaign -> 计划素材 CampaignMaterial -> 投放结果 Metric -> Agent 复盘建议
```

项目详情是主工作台。创建计划可以暂时保留独立路由，但必须由项目上下文进入，并在创建完成后回到项目详情。

## 2. 数据模型

### 2.1 CampaignMaterial

新增 `campaign_materials`，作为计划-素材关系的准数据源。

字段：

```text
id
campaign_id
material_id
title
description
copy
source
sort_order
status
created_by
created_at
updated_at
```

原则：

- 新接口优先读写 `campaign_materials`。
- 旧字段 `campaign.material_ids`、`material.campaign_ids`、`material.project_ids` 继续兼容展示和旧页面。
- 同一计划下同一素材默认唯一，后续如需要重复素材版本再拆 `variant_key`。
- 计划详情展示素材时必须带出绑定标题、描述、文案和素材本体。

### 2.2 AI Usage

新增：

- `ai_usage_logs`
- `ai_outputs`
- `ai_budgets`

原则：

- 前端不直连模型 API。
- 所有模型调用走后端 `/api/v1/ai/run`。
- AI 输出只允许是 `draft/suggested`，不得直接执行真实投放动作。
- usage log 必须记录场景、模型、token、成本、状态和 request hash。

## 3. API 合约

### 3.1 项目计划工作台

```text
GET /api/v1/projects/{project_id}/plan-workspace
```

返回：

```json
{
  "project": {},
  "platform_accounts": [],
  "campaigns": [],
  "agent_actions": [],
  "budget": {
    "total": 10000,
    "allocated": 3000,
    "unallocated": 7000,
    "spent": 1200
  }
}
```

### 3.2 批量创建计划

```text
POST /api/v1/projects/{project_id}/campaigns/batch
```

请求：

```json
{
  "plan_count": 3,
  "name_template": "DB_US_Meta_{index}",
  "platform": "Meta",
  "platform_account_id": "acct_001",
  "objective": "OUTCOME_TRAFFIC",
  "budget_type": "daily",
  "budget": 800,
  "target_cpa": 20,
  "bidding_strategy": "LOWEST_COST",
  "start_date": "2026-05-12",
  "end_date": "2026-05-26",
  "targeting": {
    "regions": ["US"],
    "age_range": { "min": 25, "max": 45 },
    "gender": "all",
    "interests": ["short drama"]
  },
  "materials": [
    {
      "material_id": "mat_001",
      "title": "短剧反转高能开场",
      "description": "面向北美女性用户，突出剧情冲突和追剧爽点。",
      "copy": "Watch the twist in episode one.",
      "source": "manual",
      "sort_order": 1,
      "status": "ready"
    }
  ]
}
```

后端校验：

- 项目存在且属于当前用户。
- `plan_count` 为 0-99。
- `budget > 0`。
- 批量预算按 `plan_count * budget` 校验，不得超过项目未分配预算。
- 平台账户必须属于当前用户；P0 可自动补项目绑定，P1 再改为强制已绑定。
- 素材必须存在且属于当前用户。
- 素材标题、描述、文案长度必须合法。

`plan_count = 0` 作为 preview/dry-run，不创建计划。

### 3.3 计划素材绑定

```text
GET    /api/v1/campaigns/{campaign_id}/materials
POST   /api/v1/campaigns/{campaign_id}/materials
PUT    /api/v1/campaigns/{campaign_id}/materials/{binding_id}
DELETE /api/v1/campaigns/{campaign_id}/materials/{binding_id}
```

兼容旧接口：

```text
POST   /api/v1/campaigns/{campaign_id}/materials/{material_id}
DELETE /api/v1/campaigns/{campaign_id}/materials/{material_id}
```

兼容策略：

- `GET` 优先返回绑定表数据。
- 如果绑定表为空，则 fallback 到旧 `material_ids`，并返回空绑定元数据。
- 新增、更新、删除绑定时同步维护旧 JSON 关系。


页面改造顺序：

5. 修复 Meta 创建分支丢失已选素材的问题。
