# v0.1 Customer Preview 客户演示脚本

## 1. 演示目标

用 15-20 分钟展示 ANIFORCE 广告投放 Agent OS 第一版能力：

- 把项目、广告账户、素材、Campaign、报表和 Agent 建议集中到一个工作台。
- 展示 Meta Campaign 创建真实链路。
- 展示系统不是普通后台，而是带右侧 AI 助手的三栏 Agent 工作台。

## 2. 演示前准备

确认：

- 前端可访问。
- 后端 `/health` 正常。
- 演示项目数据已准备：运行 `cd backend && venv/bin/python scripts/reset_customer_preview_data.py`。
- Meta 沙盒账户可见。
- 至少有一条带 `external_campaign_id` 的 Campaign。
- 数据报表页可访问并保留右侧对话框。
- Agent 行动队列没有历史脏建议。

## 3. 演示路径

### 3.1 开场：系统定位

页面：Dashboard

讲法：

> 这是 ANIFORCE 广告投放 Agent OS 的第一版客户预览。它把项目、广告账户、素材、投放计划、数据报表和 Agent 建议放到同一个工作台里，帮助投放团队减少跨平台切换和人工判断成本。

展示重点：

- 左侧功能导航。
- 中间业务工作区。
- 右侧 AI 智能助手。

### 3.2 项目管理

页面：Projects / ProjectDetail

展示：

1. 项目列表。
2. 进入项目详情。
3. 查看项目预算、状态、关联 Campaign。
4. 查看项目绑定的广告账户。
5. 查看 Agent 行动队列。

讲法：

> 项目是整个投放工作的组织单元。后续账户、素材、Campaign 和报表都会围绕项目沉淀。

验收点：

- 项目数据不出现 `test` 等脏命名。
- 项目详情能正常加载。
- 账户绑定状态正确。

### 3.3 广告账户与平台连接

页面：Platform Accounts / Settings

展示：

1. Meta 平台配置状态。
2. 已连接广告账户。
3. 账户状态、Token 状态、操作记录。
4. 说明 Google/TikTok 为后续扩展平台。

讲法：

> 第一版我们优先打通 Meta。客户可以先用 Meta 沙盒或真实授权账户完成 Campaign 创建验证，Google 和 TikTok 在后续版本按同样模式扩展。

验收点：

- Meta 账户显示清楚。
- 未完成平台不展示为可用完整能力。
- 不暴露 App Secret 或 Token。

### 3.4 创意素材

页面：Material

展示：

1. 素材列表。
2. 素材缩略图。
3. 素材状态、ROI、疲劳度、标签。
4. 素材与 Campaign 的关联。

讲法：

> 素材是 Agent 判断投放表现的重要输入。系统会把素材表现和 Campaign 数据放在同一个工作流里。

验收点：

- 图片正常显示。
- 素材状态和指标可读。
- 不出现图片 404。

### 3.5 创建广告计划

页面：CreateCampaign

展示：

1. 选择项目。
2. 选择平台和广告账户。
3. 填写预算、目标、定向和素材。
4. 创建 Campaign。
5. 展示本地 Campaign 和真实平台 Campaign ID。

讲法：

> 这里已经不是纯 Mock。Meta 链路已经支持创建真实平台 Campaign，并把平台返回的 ID 回写到本地系统，后续可以继续同步状态和效果数据。

验收点：

- 创建流程不卡死。
- 错误提示可读。
- 创建成功后能看到 Campaign。
- 如走真实 Meta 创建，能看到 `external_campaign_id`。

### 3.6 Campaign 管理

页面：Campaign / CampaignDetail

展示：

1. Campaign 列表。
2. 状态、预算、消耗、平台账户、外部 Campaign ID。
3. 进入详情。
4. 查看关联素材和基础效果。

讲法：

> 投放计划不只是列表，它会和项目预算、账户、素材、平台状态和 Agent 建议联动。

验收点：

- Campaign 数据一致。
- 已创建的 Meta Campaign 显示平台 ID。
- 素材关联关系正常。

### 3.7 数据报表

页面：Reports

展示：

1. 执行摘要。
2. 平台对比。
3. 素材排行榜。
4. 策略洞察。
5. CSV 导出。
6. 右侧 AI 对话框仍保留。

讲法：

> 报表不是独立页面，而是 Agent 工作台的一部分。用户看数据的同时可以直接让右侧助手解释异常、生成优化建议。

验收点：

- 三栏结构完整。
- 右侧对话框存在。
- 报表内容不空白。

### 3.8 Agent 行动队列

页面：ProjectDetail

展示：

1. 生成建议动作。
2. 查看风险等级。
3. 确认或拒绝建议。
4. 说明当前为最小规则版。

讲法：

> 第一版 Agent 先提供可解释建议，不直接自动花钱。下一版会进入确认后执行、结果回写和效果评估闭环。

验收点：

- 建议与当前项目事实一致。
- 已解决问题不继续展示为待处理建议。
- 确认/拒绝状态可更新。

## 4. 已知限制讲法

对客户明确说明：

- 第一版优先打通 Meta Campaign 创建。
- Ad Set / Creative / Ad 完整链路在 v0.2。
- Google/TikTok 是后续平台扩展，不作为 v0.1 验收。
- 当前 Agent 行动队列是最小规则版，先做建议和人工确认，不自动执行预算消耗。
- POC 模式可用 SQLite；试生产建议 PostgreSQL。
- Demo Mode 不等于生产权限系统。

## 5. 演示结束总结

讲法：

> v0.1 的目标是验证 Agent OS 的工作台形态和 Meta 投放主链路。接下来 v0.2 会补齐 Meta Ad Set、Creative、Ad 和平台效果同步；v0.3 会把 Agent 建议升级为确认后执行和效果复盘。
