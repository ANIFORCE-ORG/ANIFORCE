# 后端数据存储实现方案（SQLite + MongoDB 混合架构）

基于 ANIMAGUS 项目的技术框架规划文档,制定适合单机部署的后端数据存储层实现方案。

## 一、实现目标

实现三层解耦架构中的**数据层**,支持 Demo 模式和生产模式无缝切换:
- **SQLite**: 用户、投放、素材、监控等关系数据（单机轻量级方案）
- **MongoDB**: AI 对话历史和会话数据（文档存储，性能最优）
- **Redis**: 缓存、会话存储（可选，初期可用内存缓存替代）

**设计理念**: 
- SQLite 处理结构化关系数据，MongoDB 处理文档型对话数据
- 各司其职，性能最优，扩展性强
- 保持 Repository 抽象层不变，后期可无缝升级到 PostgreSQL
- 使用 Docker Compose 简化 MongoDB 部署
- 数据文件集中管理（backend/data 目录）

## 三、技术栈选型

| 组件 | 版本 | 用途 | 说明 |
|------|------|------|------|
| **SQLite** | 3.40+ | 关系数据存储 | Python 内置，零配置 |
| **SQLAlchemy** | 2.0+ | Python ORM | 统一 ORM 接口 |
| **aiosqlite** | 0.19+ | SQLite 异步驱动 | 支持 async/await |
| **Alembic** | 1.13+ | 数据库迁移 | 版本控制 |
| **MongoDB** | 7.0+ | 文档数据库 | 对话会话存储 |
| **Motor** | 3.3+ | MongoDB 异步驱动 | 与 FastAPI 完美集成 |
| ~~Redis~~ | - | ~~缓存和队列~~ | 初期用内存缓存替代 |

**混合架构优势**:
- ✅ **SQLite**：零配置，单文件，易备份，适合结构化数据
- ✅ **MongoDB**：文档模型，高性能追加，适合对话数据
- ✅ 各司其职：关系数据用 SQL，文档数据用 NoSQL
- ✅ 异步支持：aiosqlite + Motor 全异步
- ✅ 易于升级：SQLAlchemy 抽象层支持切换到 PostgreSQL
- ✅ Docker 简化：MongoDB 通过 Docker Compose 一键部署

## 四、数据库设计

### 4.0 数据层级关系

```
User (用户)
  ↓ 1:N
Project (项目) ⭐ 新增
  ↓ 1:N
Campaign (广告投放)
  ↓ 1:N
Material (素材)

Campaign → Metrics (监控数据)
```

**设计说明**:
- 添加 `projects` 表作为项目管理层级
- Campaign 通过 `project_id` 关联到 Project
- Material 同时关联 Project 和 Campaign（项目级素材管理）
- 符合前端 Projects.vue 和 Campaign.vue 页面的业务逻辑

from motor.motor_asyncio import AsyncIOMotorClient
from app.config.settings import get_settings

settings = get_settings()

# MongoDB 客户端（单例）
_client: AsyncIOMotorClient | None = None

async def get_mongodb_client() -> AsyncIOMotorClient:
    """获取 MongoDB 客户端"""
    global _client
    if _client is None:
        _client = AsyncIOMotorClient(
            settings.MONGODB_URL,
            maxPoolSize=50,
            minPoolSize=10,
            serverSelectionTimeoutMS=5000
        )
    return _client

async def get_chat_collection():
    """获取对话集合（依赖注入）"""
    client = await get_mongodb_client()
    db = client[settings.MONGODB_DB_NAME]
    return db["chat_sessions"]

async def init_mongodb_indexes():
    """初始化 MongoDB 索引"""
    collection = await get_chat_collection()
    
    # 唯一索引：session_id
    await collection.create_index("session_id", unique=True, name="idx_session_id")
    
    # 复合索引：user_id + created_at（用户会话列表）
    await collection.create_index(
        [("user_id", 1), ("created_at", -1)], 
        name="idx_user_created"
    )
    
    # TTL 索引：自动清理 90 天前的会话（可选）

    # )

class ProjectStatus(str, enum.Enum):

    PAUSED = "paused"

# app/repositories/impl/mongo_chat_repo.py
from motor.motor_asyncio import AsyncIOMotorCollection
from datetime import datetime
import uuid

class MongoChatRepository:
    """MongoDB 对话 Repository 实现"""
    
    def __init__(self, collection: AsyncIOMotorCollection):
        self._collection = collection
    
    async def create_session(self, user_id: str, game_info: dict) -> str:
        session_id = str(uuid.uuid4())
        doc = {
            "session_id": session_id,
            "user_id": user_id,
            "messages": [],
            "game_info": game_info,
            "analysis": {},
            "status": "active",
            "created_at": datetime.utcnow(),
            "updated_at": datetime.utcnow(),
        }
        await self._collection.insert_one(doc)
        return session_id
    
    async def add_message(
        self, session_id: str, role: str, content: str, 
        metadata: dict | None = None
    ) -> None:
        """高效追加消息（$push 操作）"""
        message = {
            "id": str(uuid.uuid4()),
            "role": role,
            "content": content,
            "timestamp": datetime.utcnow(),
            "metadata": metadata or {},
        }
        await self._collection.update_one(
            {"session_id": session_id},
            {
                "$push": {"messages": message},
                "$set": {"updated_at": datetime.utcnow()}
            }
        )
    
    async def get_session(self, session_id: str) -> dict | None:
        doc = await self._collection.find_one(
            {"session_id": session_id},
            {"_id": 0}
        )
        return doc
    
    async def list_sessions(self, user_id: str, limit: int = 20) -> list[dict]:
        cursor = self._collection.find(
            {"user_id": user_id},
            {"_id": 0, "messages": 0}
        ).sort("created_at", -1).limit(limit)
        return await cursor.to_list(length=limit)
```

from app.config.database import engine, Base
from app.config.mongodb import init_mongodb_indexes
from app.models import user, campaign, material, metric

async def init_databases():

    async with engine.begin() as conn:
        await conn.run_sync(Base.metadata.create_all)
    print("✅ SQLite tables created")
    
    # 2. 创建 MongoDB 索引
    await init_mongodb_indexes()
    
    print("✅ All databases initialized")

if __name__ == "__main__":
    asyncio.run(init_databases())
```

## 七、关键设计原则

### 7.1 三层解耦
- **Service 层**不直接导入 SQLAlchemy 或 Motor
- 只依赖 Repository Protocol 抽象接口
- Demo/生产模式切换通过依赖注入,Service 层代码零修改

### 7.2 异步优先
- 所有数据库操作使用 `async/await`
- PostgreSQL 使用 `asyncpg` 驱动
- MongoDB 使用 `Motor` 异步驱动
- Redis 使用 `redis.asyncio`

### 7.3 类型安全
- 所有 Repository 方法返回 `dict` 而非 ORM 对象
- Service 层不感知 ORM 模型
- 使用 Pydantic Schema 进行数据验证

### 7.4 连接池管理
- PostgreSQL: `pool_size=20, max_overflow=10`
- MongoDB: 默认连接池
- Redis: 连接池复用

## 十、后续优化

### 10.1 性能优化
1. **索引优化**: 根据查询模式添加复合索引
2. **查询优化**: 使用 SQLAlchemy 查询分析工具
3. **WAL 模式**: 启用 SQLite WAL 模式提升并发性能
4. **VACUUM**: 定期执行 VACUUM 优化数据库文件

### 10.2 升级路径
1. **升级到 PostgreSQL**: 修改 `DATABASE_URL`，Repository 层无需改动
2. **引入 Redis**: 添加缓存层，提升性能
3. **引入 MongoDB**: 对话历史迁移到 MongoDB
4. **ClickHouse 集成**: 实现 OLAP 分析能力

### 10.3 SQLite 限制与解决方案
| 限制 | 影响 | 解决方案 |
|------|------|---------|
| 并发写入受限 | 中 | 启用 WAL 模式，或升级到 PostgreSQL |
| 数据库文件大小 | 低 | SQLite 支持 TB 级数据，定期 VACUUM |
| 网络访问 | 低 | 单机部署无影响，分布式需升级 |

## 十一、风险评估

| 风险 | 影响 | 缓解措施 |
|------|------|---------|
| SQLite 并发写入冲突 | 中 | 启用 WAL 模式，合理设计事务 |
| 数据库文件损坏 | 中 | 定期备份，启用 SQLite 完整性检查 |
| 迁移失败 | 低 | 迁移前备份 .db 文件 |
| 异步代码死锁 | 低 | 代码审查，避免嵌套事务 |
