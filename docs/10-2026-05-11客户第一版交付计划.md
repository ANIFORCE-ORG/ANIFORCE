# 2026-05-11 客户第一版交付计划

## 1. 目标

本周交付 `v0.1 Customer Preview`，定位为 ANIFORCE 广告投放 Agent OS 第一版客户演示系统。

日常执行按照 `docs/11-2026-05-11多Agent协作执行规程.md` 进行。每天不重新规划全局，而是由项目经理 Agent 恢复上下文、确认当日目标，再协调产品、前端、后端、API、数据库部署、测试和发布交付角色推进到当天任务完成。

第一版不承诺完整广告投放平台，而是交付一条可演示、可解释、可继续迭代的主链路：

1. 项目管理：建立客户/产品/投放项目。
2. 广告账户：连接或导入 Meta 广告账户，查看账户状态和操作记录。
3. 创意素材：管理素材、查看素材表现、关联投放计划。
4. 广告计划：从项目和账户出发创建 Campaign，并展示真实 Meta Campaign ID。
5. 数据报表：汇总消耗、安装、ROI、平台对比、素材排行和策略洞察。
6. Agent 行动队列：基于账户、预算、计划状态给出建议，支持确认/拒绝。
7. 右侧 AI 助手：核心页面保持左导航、中工作区、右对话框的三栏系统结构。

客户价值主张：

> 帮助投放团队把项目、广告账户、素材、Campaign、报表和 Agent 建议放到同一个工作台里，并打通 Meta Campaign 创建的真实链路。

## 2. 版本范围

## 2.1 完整系统交付范围

本次客户交付不是单纯前端 Demo，也不是只交付 API。交付对象应定义为一套可部署、可启动、可演示、可继续运维的前后端完整系统。

交付范围包含：

1. 前端应用：Vue3 主应用、路由、页面、组件、构建产物。
2. 后端服务：FastAPI API 服务、业务 Service、Repository、平台连接适配器。
3. 数据库：开发/演示可用 SQLite；客户部署需明确是否升级 PostgreSQL，并提供迁移策略。
4. 权限与认证：Demo 模式固定用户；客户环境需至少提供管理员账号、访问控制边界和 Token/JWT 配置。
5. 平台连接：Meta 作为第一版真实平台；OAuth Redirect、App ID、App Secret、Token 存储和沙盒账户配置必须可说明。
6. 网络环境：域名、HTTPS、CORS、前后端访问地址、反向代理、端口暴露。
7. 部署脚本：启动、停止、健康检查、日志查看、环境变量配置。
8. 运维基线：备份、日志、监控、故障恢复、已知限制。
9. 交付材料：部署手册、演示脚本、账号清单、配置清单、验收清单。

## 2.3 数据库规划

### 当前数据库判断

当前系统适合本地演示和客户预览，但还不是严格生产数据库交付形态。第一版可按两种模式交付：

模式 A：客户演示/POC

- 数据库：SQLite。
- 优点：部署简单，适合快速演示。
- 风险：并发、备份、权限隔离、远程运维能力有限。
- 适用：内部试用、单客户演示、短期 POC。

模式 B：客户生产试点

- 数据库：PostgreSQL。
- 优点：更适合多用户、多项目、长期数据、备份恢复。
- 风险：本周需要补部署配置、迁移验证和连接池设置。
- 适用：客户要真实使用、长期留存数据、多人访问。

### 第一版建议

本周交付建议采用：

- 默认交付：SQLite POC 模式。
- 文档中明确：生产部署建议升级 PostgreSQL。
- 同时准备 PostgreSQL 迁移规划，但不把 PostgreSQL 完整生产化作为本周验收硬门槛，除非客户明确要求。

### 数据库 P0 交付要求

- 明确数据库文件位置或连接地址。
- 明确初始化数据方式。
- 明确迁移命令和当前 migration revision。
- 提供演示数据重置方式。
- 交付前清理脏数据：
  - 删除 `test` 这类不可展示项目。
  - 清理历史不一致 Agent 建议。
  - 保留一组稳定演示项目、账户、Campaign、素材、报表数据。
- 明确哪些数据是沙盒真实数据，哪些是 Demo 数据。

### 数据库 P1 交付要求

- PostgreSQL 部署说明。
- 备份脚本。
- 恢复脚本。
- 数据字典。
- 关键表说明：
  - users

  - campaigns
  - materials

## 2.5 网络、域名与部署规划

### 当前网络风险

- 本地测试主要使用：
  - 前端：`http://127.0.0.1:3010`
  - 后端：`http://127.0.0.1:8010`
- 文档历史中出现过 `3011`，端口口径需要统一。
- Meta OAuth redirect 曾出现 localhost HTTPS 地址，客户环境不可直接使用。
- CORS 当前需要按客户域名配置。

### 第一版部署拓扑

推荐 POC 部署拓扑：

```
Browser
  |
  | HTTPS
  v
Nginx / Caddy / Cloud Reverse Proxy
  |                       |
  | /                     | /api
  v                       v
Frontend Static/Vite      FastAPI Backend
                          |
                          v
                      SQLite / PostgreSQL
```

### 端口规划

本地开发：

- 前端：`3010`
- 后端：`8010`

客户 POC：

- 对外只暴露 HTTPS `443`。
- 前端通过根路径访问。
- 后端通过 `/api/v1` 代理访问。
- 后端内部端口仍可使用 `8010`，不直接对公网暴露。

### 域名和 HTTPS

P0 要求：

- 客户环境必须使用 HTTPS 域名。
- Meta OAuth Redirect URI 必须配置为客户域名下的后端回调地址，例如：
  - `https://客户域名/api/v1/platform/meta/oauth/callback`
- 前端回调地址必须配置为：
  - `https://客户域名/platform-accounts/callback`
- CORS 必须包含客户前端域名。

### 环境变量清单

后端必需：

- `DEMO_MODE`
- `DEBUG`
- `CORS_ALLOW_ORIGINS`
- `JWT_SECRET`
- `JWT_ALGORITHM`
- `DATABASE_URL` 或 SQLite 数据库路径
- `FRONTEND_BASE_URL`
- `META_APP_ID`
- `META_APP_SECRET`
- `META_OAUTH_REDIRECT_URI`
- `META_PROXY_URL`，如客户网络访问 Meta 需要代理

前端必需：

- `VITE_API_BASE_URL`
- `VITE_DEMO_MODE`，如仍保留 Demo 客户端逻辑

### 网络 P0 交付要求

- 固定启动脚本。
- 固定停止脚本。
- 固定健康检查：
  - 前端首页 HTTP 200。
  - 后端 `/health` HTTP 200。
  - 核心 API HTTP 200。
- 输出客户部署域名、端口、CORS、OAuth redirect 的配置表。
- 说明客户网络是否能访问：
  - Meta Graph API
  - Google Ads API，未来
  - TikTok API，未来
- 如果需要代理，必须明确代理地址和部署位置。
