# 数据库交付与演示数据方案 v0.1

## 1. 目标

v0.1 需要保证客户演示数据稳定、可解释、可恢复。

数据库交付目标：

- 明确 POC 和试生产数据库模式。
- 明确演示数据和真实平台数据的区别。
- 明确备份、恢复、重置方式。
- 避免客户看到脏数据、历史测试数据和状态不一致数据。

## 2. 数据库模式

### 2.1 SQLite POC

适用：

- 客户预览。
- 单用户演示。
- 本周 v0.1 默认模式。

特点：

- 部署简单。
- 便于复制备份。
- 不适合多人生产并发。

交付要求：

- 明确数据库文件路径。
- 演示前备份。
- 演示后可恢复。
- 不承诺生产级权限隔离和高可用。

### 2.2 PostgreSQL 试生产

适用：

- 客户多用户试用。
- 真实项目数据。
- 长期数据留存。

交付要求：

- 独立数据库。
- 独立数据库用户。
- 强密码。
- 每日备份。
- 保留 7 天。
- 明确迁移命令。

## 3. 数据分类

| 数据类型 | 说明 | 是否可用于客户演示 | 注意事项 |
|---|---|---:|---|
| 演示项目数据 | 为演示准备的项目、预算、Campaign、素材 | 是 | 命名必须客户可读 |
| 沙盒平台数据 | Meta 沙盒账户、沙盒 Campaign ID | 是 | 标注为沙盒 |
| 真实平台数据 | 客户授权平台返回数据 | 视客户确认 | 不默认创建真实消耗 |
| 历史测试数据 | `test`、临时创建、调试残留 | 否 | 交付前清理 |
| Mock 素材数据 | 本地素材和指标 | 是 | 需说明非真实平台回传 |

## 4. v0.1 推荐演示数据集

至少准备：

1. 一个客户可读项目。
2. 一个已绑定 Meta 沙盒账户。
3. 两到三条 Campaign。
4. 至少一条 Campaign 带 `external_campaign_id`。
5. 十条以上素材。
6. 报表页有汇总指标。
7. Agent 行动队列有一到两条合理建议，或展示“当前无关键风险”。

命名建议：

- 项目：`EASTAR Games - 北美增长测试`
- Campaign：`NA Install Test - Meta Traffic`
- 素材：`UGC Hook - Level 15`

避免：

- `test`
- `测试项目1`，对外演示建议改为客户可读命名
- 无意义 UUID 直接显示
- 已解决但仍显示的历史建议

## 5. 演示前数据清理清单

必须检查：

- 项目名是否客户可读。
- Campaign 是否关联正确项目。
- Campaign 是否显示平台账户。
- Meta Campaign 是否显示外部 ID。
- 素材图片是否可加载。
- 报表是否有数据。
- Agent 建议是否与当前事实一致。
- 没有“已绑定账户但仍建议绑定账户”的历史脏建议。

## 6. 备份策略

### 6.1 SQLite

演示前：

1. 停止服务。
2. 复制数据库文件到备份目录。
3. 记录备份时间。
4. 启动服务。
5. 跑健康检查。

演示后恢复：

1. 停止服务。
2. 用备份数据库覆盖当前数据库。
3. 启动服务。
4. 跑健康检查。

### 6.2 PostgreSQL

每日：

1. `pg_dump`。
2. 上传或复制到备份目录。
3. 保留 7 天。
4. 记录备份状态。

恢复：

1. 暂停服务。
2. 备份当前库。
3. 恢复指定备份。
4. 启动服务。
5. 跑核心 API。

## 7. 迁移策略

v0.1：

- 保持当前 SQLite POC 可用。
- 文档说明 PostgreSQL 是试生产推荐。

v0.2：

- 明确 Alembic migration 命令。
- 为 PostgreSQL 做一次干净库迁移验证。
- 补数据字典。

v0.3：

- 数据备份自动化。
- 数据恢复演练。
- 增加操作审计表。
