## 2. v0.3 目标

把 v0.2 的 AI Gateway 从“后端能力”升级成“业务人员可用的 AI 协作能力”：

```text
右侧助手理解当前项目/计划上下文
  -> 受控调用 AI Gateway
  -> 返回结构化建议
  -> 业务人员选择应用
  -> 系统落表/创建草稿/保存复盘
  -> usage/token 可视化
```

## 3. P1 范围

### P1-1 ChatPanel 接入 AI Gateway

目标：

- ProjectDetail 和 CampaignDetail 的右侧助手不再只 `console.log`。
- 根据当前页面上下文调用 `/api/v1/ai/run`。
- 固定场景：
  - ProjectDetail：`plan_extract`、`material_recommend`、`chat_general`
  - CampaignDetail：`campaign_diagnosis`、`report_summary`、`chat_general`
- 输出只作为消息展示，不直接执行业务动作。

验收：

- 输入“分析这个项目”能返回 AI Gateway mock 建议。
- 输入“生成复盘”能返回 report summary。
- 消息中展示 token 消耗。

### P1-2 素材标题/描述生成 3 个候选

目标：

- CreateCampaign 素材绑定输入区增加“生成候选”按钮。
- 调用 `material_copy` 场景。
- 返回 3 个候选标题/描述。
- 用户点击候选后填入当前素材绑定表单。

验收：

- 每个素材可独立生成候选。
- 生成结果不自动保存，必须人工应用。
- usage log 可查。

### P1-3 AI 使用量看板

目标：

- 在 Settings 或独立页面展示 AI usage summary/logs。
- 可设置用户日 token 限额。
- 展示 provider、model、scenario、tokens、cost、status。

验收：

- 能看到 `material_copy/report_summary/campaign_diagnosis` 调用记录。
- 能设置 daily token limit。

### P1-4 复制计划进入确认

目标：

- CampaignDetail 提供“复制计划”入口。
- 带 projectId 和 copyFromCampaignId 进入创建页。
- P1 先填充基础信息和素材绑定，直接进入确认或素材步骤。

验收：

- 复制计划不会直接创建。
- 用户确认后才提交 batch create。

## 4. P2 范围

### P2-1 真实 OpenAI Provider

目标：

- 在 AI Gateway provider 层接入真实 OpenAI API。
- 保留 mock provider。
- 根据场景选择 small/medium/large model。
- 真实 usage 映射到 `ai_usage_logs`。

约束：

- 前端不直连模型。
- 所有输出必须通过 schema 校验。
- 超预算拒绝调用。

### P2-2 策略生成

目标：

- 新增场景 `strategy_generate`。
- 输入项目、计划、素材、投放结果。
- 输出投放策略草稿：
  - 目标市场。
  - 预算建议。
  - 素材组合。
  - 风险点。
  - 人工确认项。

### P2-3 素材推荐

目标：

- `material_recommend` 根据项目/计划和素材库返回候选素材。
- 业务人员选择后加入计划素材绑定。

### P2-4 Token 成本优化

目标：

- request hash 缓存。
- 场景上下文裁剪。
- 大对象摘要化。
- 失败重试和限流。

## 5. v0.3 执行顺序

Day 1：

- ChatPanel 接 AI Gateway。
- ProjectDetail/CampaignDetail 接入上下文。
- 记录调用 usage。

Day 2：

- 素材文案 3 候选。
- 应用候选到素材绑定表单。
- 业务测试。

Day 3：

- AI usage 看板。
- Token budget 设置。
- 复测预算超限。

Day 4：

- 复制计划入口。
- copy preview 后端/前端最小实现。

Day 5：

- 真实 OpenAI Provider 设计和 mock/real provider 边界。
- 如有密钥则做真实调用冒烟；无密钥则保持 mock。

Day 6：

- 策略生成与素材推荐 P2 设计/最小接口。

Day 7：

- 全链路测试、文档、冻结和远端备份分支。

## 6. 测试原则

继续沿用：

1. 多线程并行协作。
2. 以实际交付业务流程进行测试。
3. 客户交付标准。
4. 非必要不中断连续开发。
