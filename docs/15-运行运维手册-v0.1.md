# ANIFORCE v0.1 运行运维手册

## 1. 适用范围

本文用于 v0.1 Customer Preview 的本地、POC 和客户试点部署。

覆盖：

- 前端启动和构建。
- 后端启动和健康检查。
- 环境变量。
- 数据库初始化、备份和恢复。
- 日志查看。
- 常见故障处理。

## 2. 环境类型

### 2.1 本地开发环境

用途：

- 开发和调试。
- 不承诺稳定运行。

默认：

- 前端：`http://127.0.0.1:3010`
- 后端：`http://127.0.0.1:8010`
- API：`http://127.0.0.1:8010/api/v1`

### 2.2 客户 POC 环境

用途：

- 客户演示。
- 单用户或小范围试用。

推荐：

- 前端和后端通过同一个 HTTPS 域名访问。
- 对外只暴露 `443`。
- 后端通过反向代理暴露 `/api/v1` 和 `/health`。
- 数据库默认 SQLite。

### 2.3 客户试生产环境

用途：

- 多人试用。
- 真实客户项目数据。

推荐：

- PostgreSQL。
- `DEMO_MODE=false`。
- 启用真实登录和 JWT。
- 配置日志、备份和健康检查。

## 3. 启动方式

### 3.1 一键脚本

推荐使用仓库根目录脚本：

```bash
./run_server.sh
```

默认端口：

- 前端：`3010`
- 后端：`8010`

指定端口：

```bash
./run_server.sh --frontend-port 3010 --backend-port 8010
```

云端模式：

```bash
./run_server.sh --mode cloud --skip-install
```

### 3.2 停止服务

```bash
./stop_server.sh
```

指定端口：

```bash
./stop_server.sh --frontend-port 3010 --backend-port 8010
```

## 4. 构建检查

前端严格构建：

```bash
cd frontend/packages/main-app
npm run build
```

前端 Vite 打包：

```bash
cd frontend/packages/main-app
npm exec vite build
```

后端 Python 编译检查：

```bash
python3 -m compileall backend/app
```

交付前必须通过：

- `npm run build`
- `python3 -m compileall backend/app`
- 核心 API 冒烟测试

## 5. 健康检查

后端：

```bash
curl -s http://127.0.0.1:8010/health
```

期望：

```json
{
  "status": "ok",
  "demo_mode": true,
  "timestamp": 0
}
```

核心 API：

```bash
curl -s http://127.0.0.1:8010/api/v1/projects
curl -s http://127.0.0.1:8010/api/v1/campaigns
curl -s http://127.0.0.1:8010/api/v1/materials

curl -s http://127.0.0.1:8010/api/v1/media-ops/dashboard
curl -s http://127.0.0.1:8010/api/v1/platform/connections/meta/config
```

前端：

## 6. 环境变量

### 6.1 后端

必填：

```bash
DEMO_MODE=true
DEBUG=true
CORS_ALLOW_ORIGINS=http://127.0.0.1:3010,http://localhost:3010
JWT_SECRET=replace-with-strong-secret
JWT_ALGORITHM=HS256
FRONTEND_BASE_URL=http://127.0.0.1:3010
META_APP_ID=
META_APP_SECRET=
META_OAUTH_REDIRECT_URI=http://127.0.0.1:8010/api/v1/platform/meta/oauth/callback
META_PROXY_URL=
```

生产/试点额外建议：

```bash
DEMO_MODE=false
DEBUG=false
CORS_ALLOW_ORIGINS=https://客户域名
FRONTEND_BASE_URL=https://客户域名
META_OAUTH_REDIRECT_URI=https://客户域名/api/v1/platform/meta/oauth/callback
```

### 6.2 前端

本地：

```bash
VITE_API_BASE_URL=/api/v1
```

如果前端不通过代理访问后端：

```bash
VITE_API_BASE_URL=http://127.0.0.1:8010/api/v1
```

客户环境推荐：

```bash
VITE_API_BASE_URL=/api/v1
```

## 7. 数据库运维

### 7.1 SQLite POC

适合：

- 客户演示。
- 单用户 POC。

备份：

```bash
# 示例，实际路径以部署环境为准
cp backend/data/app.db backups/app-$(date +%Y%m%d-%H%M%S).db
```

恢复：

```bash
./stop_server.sh
cp backups/app-YYYYMMDD-HHMMSS.db backend/data/app.db
./run_server.sh --skip-install
```

要求：

- 演示前备份。
- 演示后如需要，恢复干净数据。
- 不直接用于多人生产环境。

### 7.2 PostgreSQL 试生产

备份：

```bash
pg_dump "$DATABASE_URL" > backups/animagus-$(date +%Y%m%d-%H%M%S).sql
```

恢复：

```bash
psql "$DATABASE_URL" < backups/animagus-YYYYMMDD-HHMMSS.sql
```

要求：

- 每日备份。
- 保留 7 天。
- 恢复前先备份当前库。
- 恢复后跑健康检查和核心 API。

## 8. Meta OAuth 配置

本地 POC：

```text
http://127.0.0.1:8010/api/v1/platform/meta/oauth/callback
```

客户环境：

```text
https://客户域名/api/v1/platform/meta/oauth/callback
```

Meta App 侧必须配置：

- App Domains：客户域名。
- Valid OAuth Redirect URIs：后端回调地址。
- Required Scopes：
  - `ads_management`
  - `ads_read`
  - `business_management`

安全要求：

- `META_APP_SECRET` 不写入前端。
- Token 不输出到日志。
- 客户文档不明文记录生产 Secret。

## 9. 日志与排障

优先查看：

1. 后端启动日志。
2. 前端 Vite 或静态服务日志。
3. 反向代理日志。
4. Meta API 错误信息。
5. 数据库连接错误。

常见问题：

| 问题 | 排查 |
|---|---|
| 前端打不开 | 检查前端服务、反向代理、端口、HTTPS |
| API 404 | 检查代理路径是否保留 `/api/v1` |
| API CORS 错误 | 检查 `CORS_ALLOW_ORIGINS` |
| 登录失败 | 检查 `DEMO_MODE`、`JWT_SECRET`、Token |
| Meta OAuth 失败 | 检查 Redirect URI、App Domain、App Secret |
| Campaign 创建失败 | 检查平台 Token、账户权限、Meta API 错误 |
| 报表空白 | 检查 Campaign/素材/指标数据是否初始化 |

## 10. 发布前检查

必须完成：

- 前端严格构建通过。
- 后端编译检查通过。
- 后端健康检查通过。
- 核心 API 冒烟通过。
- 前端核心路由可访问。
- 数据库已备份。
- 演示数据已清理。
- Meta OAuth Redirect 已配置。
- CORS 已配置。
- 已知限制已写入客户文档。

## 11. 回滚策略

POC：

1. 停止服务。
2. 恢复上一份数据库备份。
3. 切回上一份前端构建产物或 Git commit。
4. 重启服务。
5. 跑健康检查。

试生产：

1. 暂停入口流量。
2. 回滚应用版本。
3. 如涉及数据库迁移，按迁移脚本说明回滚或恢复备份。
4. 恢复流量。
5. 跑核心链路验证。
