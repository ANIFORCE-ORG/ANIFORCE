# 信优媒介运营系统接入规划

## 背景

信优媒介飞书 SOP 描述了线下广告账户媒介团队的日常流程：

```text
客户进群 -> 下户工单 -> 金额核算/收款 -> 开户 -> 绑卡设限额 -> 登记账户 -> 交付客户 -> 充值/像素/验证/冻结等售后
```

该流程和蓝鲸数字营销平台的账户资源运营后台高度相似。ANIFORCE 当前已经具备广告投放 Agent、平台连接、广告账户、素材、项目和报表等模块，因此本次先把信优媒介流程作为独立的 `media_ops` 业务模块接入，后续再合并进统一 Agent OS。

## 产品模块规划

### 1. 工作台

用于媒介、财务、运营主管查看每日待办：

- 今日下户
- 待处理订单
- 水单待审
- 待交付账号
- 未结工单
- 今日应收
- 下户订单状态漏斗
- 风险提醒

### 2. 客户管理

后续正式化字段：

- 客户名称
- 行业
- 等级
- 联系群
- 付款偏好
- 对接媒介
- 风险备注

### 3. 账户产品 / 户类型

把线下“户类型”产品化：

- Facebook 三不限账户
- Facebook Club 账户
- 欧洲海外户
- 后续扩展 TikTok / Google

字段：

- 平台
- 户类型
- 账户属性
- 可投行业
- 最低充值
- 交付 SLA
- 卖点 / 限制 / 风险提示

### 4. 下户订单

状态流：

```text
草稿 -> 待付款 -> 水单审核 -> 待开户 -> 开户中 -> 绑卡设限额 -> 待交付 -> 已交付 / 异常
```

字段：

- 客户
- 产品
- 户类型
- 时区
- 邮箱
- 数量
- 投放行业
- 付款方式
- 应收金额
- 负责人
- 下一步动作

### 5. 财务水单

将群里发水单改为系统审核：

- 订单号
- 客户
- 金额
- 币种
- 交易哈希
- 水单截图
- 审核状态
- 审核人
- 审核时间

### 6. 广告账户交付

和现有 `PlatformAccount` 模块存在交叉，正式合并时建议：

- 平台授权账户继续走 `platform_accounts`
- 媒介供应账户走 `media_accounts` 或扩展 `PlatformAccount.source_type = agency-provided/rented`
- 通过 `account_operations` 记录充值、清零、绑定、回收

### 7. 售后工单

类型：

- 像素绑定
- 账户验证
- 冻结 / 解冻
- 账户迁移
- 充值延迟
- 限额调整
- 封禁申诉

### 8. 知识库

沉淀标准话术：

- 开户工单必填字段
- 充值对接规则
- 像素绑定话术
- 冻结/解冻处理
- 账户迁移说明

## 和现有 ANIFORCE 的整合点

### 平台账户

现有：

- `backend/app/models/platform_account.py`
- `/api/v1/platform/accounts`
- `/platform-accounts`

建议：

- 媒介交付的账号最终进入 `PlatformAccount`
- `source_type` 标记为 `agency-provided`、`rented` 或 `internal-supply`
- 将媒介订单 ID 写入备注或新增关联表

### Agent 诊断

媒介运营数据可以给 Agent 提供新的判断：

- 账户是否已交付但未接收
- 账户是否冻结/封禁
- 账户是否需要充值
- 充值是否超时
- 工单是否超 SLA
- 客户是否存在付款/风险异常

### 财务和预算

短期：

- 先作为媒介运营模块内部数据。

长期：

- 与项目预算、广告账户余额、投放消耗统一到一个预算和资金视图。

## 下一步开发建议

1. 把 `media_ops.py` 的内存数据迁移到 SQLAlchemy 模型和 Alembic migration。
2. 增加下户订单创建表单和状态流转按钮。

5. 增加工单创建、分配、SLA 超时提醒。
6. 把知识库接入 Agent 对话，客户问题自动推荐标准话术。

## 当前实现性质

本次实现是“可运行的功能原型”，不是最终数据库版本。代码刻意独立，方便后续统一合并进 Agent OS。
